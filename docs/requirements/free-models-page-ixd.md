## 1. 目标与范围

### 1.1 页面价值

- **用户价值**：在一个页面内完成「每日免费大模型」的接入、开关、统计与日常管理，降低多模型切换心智与成本。
- **产品目标**：提升免费额度利用率、减少付费调用、统一管理多 Provider 的免费账号。

### 1.2 文档范围

- 本页为**单页应用**，无子路由；所有能力通过区块、弹窗与列表在同一视图内完成。
- 不包含：路由外的登录/鉴权、控制台整体导航与布局（沿用现有规范）。

## 3. 页面状态定义

### 3.1 状态枚举

| 状态 ID   | 说明                     | 主内容区展示           |
|-----------|--------------------------|------------------------|
| `loading` | 首屏拉取配置/Provider 列表 | 骨架屏（保持布局稳定） |
| `empty`   | 无配置、未开启、且未打开弹窗 | 空状态引导             |
| `with_data` | 有配置或已开启           | 统计区 + 开关 + 列表   |
| `error`   | 接口/操作报错（可与上述并存） | 原内容 + 顶部错误条    |

### 3.2 状态与弹窗关系

- **空状态 + 打开配置弹窗**：主内容区**不再展示空状态卡片与引导**，仅保留标题区 + 错误条（若有）+ 弹窗，避免双层内容叠加。
- **有数据 + 打开配置/删除弹窗**：主内容区保持，仅叠加一层弹窗；**同一时刻仅一个业务弹窗**（配置 或 删除确认）。

### 3.3 加载与错误

- **加载**：进入页面或刷新时，若正在请求配置/Provider，显示骨架屏；数据返回后切到 `empty` 或 `with_data`。
- **错误**：任意请求或操作失败时，在标题区下方展示**单条全局错误提示**，带关闭（×）；关闭后该条不再展示，直到下一次报错。

## 4. 用户流程（关键任务）

### 4.1 流程一：首次使用 — 从零到第一个免费模型

1. 进入页面 → 看到空状态（说明 + 特性标签 + 可配置 Provider 卡片）。
2. 点击某 Provider 卡片或「立即配置」→ 空状态隐藏，弹出「配置 [Provider]」弹窗。
3. 在弹窗内输入 API 密钥（必填）；未填时「测试连接」「保存配置」禁用。
4. 填写后点击「测试连接」→ 按钮进入 loading（如「验证中…」），结果在弹窗内展示（成功/失败）。
5. 仅当测试成功时「保存配置」可点；点击后发起保存。
6. **保存成功后自动关闭弹窗**，无需用户手动关闭；主内容区变为「有数据」并展示统计区与列表。**保存失败也自动关闭弹窗**，并在页面顶部展示可关闭的错误条。

### 4.2 流程二：开启/关闭「自动切换」

1. 在「有数据」状态下，于统计区下方看到总开关。
2. 切换开关 → 立即生效（无需二次确认）；请求失败则开关恢复原状态并在顶部展示错误条。

### 4.3 流程三：管理已配置模型（首选、删除）

- **设为首选**：在已配置列表中点击某条的「设为首选」→ 请求成功后列表与首选标识即时更新。
- **删除**：点击某条的「删除」→ 弹出删除确认弹窗 → 用户确认后执行删除并关闭弹窗、刷新列表；失败则关闭弹窗并展示顶部错误条。

### 4.4 流程四：再添加一个免费模型

1. 在「可添加列表」中点击某 Provider 的「配置」。
2. 与「流程一」中弹窗行为一致：配置 → 测试连接 → 保存后关闭弹窗并刷新列表。

## 5. 交互规范（按模块）

### 5.1 页面标题区

- **主标题**：固定文案「ClawdbotCN 独家福利」。
- **副标题**：固定文案「每日免费大模型平滑切换工具」。
- **交互**：纯展示，无点击。

### 5.2 全局错误条

- **触发**：任意接口错误或操作失败。
- **内容**：一句用户可读的失败原因（如「保存失败：网络错误」），避免裸技术信息。
- **交互**：右侧提供关闭（×）；关闭后该条消失，不自动复现直至下次报错。
- **布局**：标题区正下方，全宽，不遮挡标题。

### 5.3 空状态引导

- **展示条件**：当前无任何已配置账号 **且** 未开启「每日免费大模型平滑切换」 **且** 未打开配置弹窗。
- **内容**：
  - 一句说明：免费模型是什么、能带来什么（省钱、自动切换）。
  - 若干**特性标签**（如：每日 50 万免费 Token、自动无感切换、日省 ¥5–10）。
  - **可配置 Provider 卡片**：每卡展示名称、每日额度、简短特性 +「立即配置」按钮。
  - 底部说明：可同时配置多个模型，系统按优先级自动切换。
- **交互**：点击卡片或「立即配置」→ 打开该 Provider 的配置弹窗；**此时空状态内容隐藏**。

### 5.4 统计区

- **展示条件**：有至少一个已配置账号 或 已开启总开关。
- **内容与顺序**：今日已省（¥，主强调）→ 累计节省（¥）→ 免费调用次数 → 可用模型数/总配置数（如 1/1）。
- **交互**：纯展示；数字与单位清晰（¥、次），主指标视觉权重最大。

### 5.5 总开关

- **位置**：统计区下方、已配置列表上方。
- **主文案**：如「启用每日免费大模型平滑切换」。
- **副文案**：如「额度用完自动切换到下一个免费模型」。
- **交互**：Toggle/Checkbox，切换即生效；失败则恢复原状态 + 顶部错误条。

### 5.6 已配置的免费模型列表

- **每条卡片内容**：Provider 名称、状态（可用/额度用完/错误）、今日使用量/每日额度、重置时间、首选标识（若有）、操作「设为首选」「删除」。
- **排序**：按优先级，首选在最前。
- **交互**：
  - 「设为首选」：点击即请求，成功后更新列表与标识。
  - 「删除」：点击 → 弹出删除确认弹窗 → 确认后执行删除并刷新。

### 5.7 可添加的免费模型列表

- **内容**：仅展示当前**未配置**的 Provider：名称、每日额度、「配置」按钮。
- **交互**：点击「配置」→ 打开该 Provider 的配置弹窗（与空状态入口同流程）。

### 5.8 配置弹窗（单 Provider）

- **标题**：「配置 [Provider 名称]」（如「配置 蚂蚁百灵」）。
- **说明**：每日免费额度、重置时间（如每日 00:00 北京时间）。
- **表单**：API 密钥（必填，密码型输入）；「获取 API 密钥」为外链（新窗口）。
- **按钮**：「测试连接」「保存配置」；右上角关闭（×）。
- **状态与规则**：
  - 未输入密钥：「测试连接」「保存配置」禁用。
  - 输入密钥后：「测试连接」可用；点击后按钮 loading（如「验证中…」），结果在弹窗内展示。
  - 仅当「测试连接」成功时「保存配置」可用；点击后发起保存。
  - **保存成功或失败后均自动关闭弹窗**，无需用户手动关闭；失败时在页面顶部展示错误条。

### 5.9 删除确认弹窗

- **标题**：「确认删除」。
- **说明**：将删除 [Provider 名称] 的配置及后果（无法再用该免费额度）。
- **按钮**：「取消」「确认删除」。
- **交互**：遮罩或「取消」→ 关闭弹窗；「确认删除」→ 执行删除并关闭、刷新列表；失败则关闭弹窗 + 顶部错误条。

### 5.10 切换历史（可选）

- **内容**：最近若干条切换记录（时间、从哪到哪、原因、节省金额等）。
- **展示**：有数据时展示区块；无数据可不展示、不占位。

## 6. 组件与反馈规范

### 6.1 按钮与可点击元素

- 主操作（保存、确认删除）：使用主按钮样式。
- 次要操作（取消、关闭）：使用次要或文本样式。
- 禁用态：与主题一致，明确不可点击（对比度与可访问性见 7）。

### 6.2 异步操作反馈

- 测试连接、保存、设为首选、删除、总开关：进行中需有 loading 状态（如按钮文案/ spinner），防止重复提交。
- 成功：更新界面数据，不强制 toaster（若已有列表/统计刷新即可理解）。

### 6.3 弹窗层级与焦点

- 弹窗带遮罩；关闭方式：×、取消、点击遮罩（可选，与现有控制台规范一致）。
- 同一时刻仅一个业务弹窗；弹窗打开时焦点移入弹窗，关闭后焦点回到触发元素或合理默认位置。

### 6.4 表单校验

- 配置弹窗：必填项（API 密钥）未填时，不提交、按钮禁用即可；无需单独 inline 报错，减少干扰。

## 7. 无障碍与主题

### 7.1 视觉与主题

- 全页使用**设计 token**（如 `--text-strong`、`--muted`、`--card`、`--border`、`--danger` 等），保证浅色/深色主题下对比度一致。
- 错误条、统计数字、按钮、链接在两种主题下均易读、易辨、可点击。

### 7.2 无障碍

- 弹窗内文案、输入框、按钮满足对比度要求；按钮可点击状态明确（禁用态不与「可点」混淆）。
- 错误条可被屏幕阅读器朗读；关键操作具备可读的 name/aria 描述（与现有控制台规范一致）。

## 8. 数据与接口依赖

- **数据来源**：Gateway 的 `freeModels` 相关接口（如 `freeModels.config.get`、`freeModels.providers`、账户的 add/remove/test/reorder 等）；页面不本地持久化，以接口为准。
- **结构**：含 `enabled`、`accounts`、`scheduling`、`stats`、`switchHistory` 等；前后端对 `freeModels` 的 schema 保持一致（如保留 `scheduling`），避免保存时报未识别字段。

## 附录：前端实现备注

以下为前端技术视角的补充，便于实现时少踩坑、与现有控制台一致。

### 状态与弹窗的 UI 实现

- **空状态 + 配置弹窗**：文档要求「打开弹窗时空状态内容不展示」。建议用**同一条件**驱动：`showConfigModal !== null` 时主内容区不渲染空状态区块，只渲染标题区 + 错误条；弹窗作为 overlay 独立渲染。避免用「弹窗盖住空状态」的 z-index 方案，否则无障碍与焦点会混乱。
- **状态派生**：`loading` / `empty` / `with_data` 可由「接口数据 + 弹窗是否打开」派生，不必单独维护一个 state 枚举；但若用枚举，务必保证「打开配置弹窗」时主内容区展示逻辑与文档一致（空状态不出现）。

### 错误条

- **单例、可关闭**：全局只保留一条错误文案；关闭后清掉 state，下次报错再设。建议用 React 等状态提升到页面级，或轻量 store，避免多个组件各自 toaster 导致重复条。
- **文案**：后端若返回技术错误码，前端应做一层映射为可读短句（如「保存失败：网络错误」），文档已要求「避免裸技术信息」。

### 配置弹窗：保存后自动关闭

- 在保存请求的 **then / catch / finally** 里统一执行「关闭弹窗」+「成功则刷新列表/统计，失败则设置全局错误条」。不要等用户点 × 才关。
- 若「测试连接」与「保存」共用同一弹窗内的表单，保存并关闭后再次打开时需**清空**上一次的密钥与测试结果，避免误用旧数据。

### 接口与数据

- 文档写「含 `scheduling` 等」「前后端 schema 一致」：前端在提交 config 时不要 strip 掉后端已声明的字段，否则可能触发「未识别字段」或误删用户配置。若使用 zod 等做请求体校验，schema 要与后端对齐。
- 列表的「优先级/首选」若由后端返回顺序或字段表示，前端以接口为准展示即可；「设为首选」/ 排序的请求成功后，建议**以全量列表/配置再拉一次**或用接口返回的完整数据更新本地 state，避免只做本地 reorder 与后端不一致。

### 与现有控制台一致

- **Design tokens**：全页使用 `ui/src/styles/base.css` 中的 CSS 变量（`--card`、`--text-strong`、`--muted`、`--border`、`--accent`、`--danger` 等），不硬编码色值，以兼容浅色/深色主题。
- **弹窗/按钮**：复用控制台已有的 Modal、Button、Alert 等组件与交互（遮罩、×、取消、焦点陷阱），保证行为与无障碍一致。
- **骨架屏**：若控制台已有统一的 loading 骨架，本页首屏拉取时直接复用，避免布局跳动。

### 可选实现细节

- **点击遮罩是否关弹窗**：文档写「可选，与现有控制台规范一致」；若现有弹窗是点遮罩可关，本页保持一致即可。
- **切换历史**：「有数据时展示」；若接口暂无或暂不实现，可不渲染该区块，不占位，符合文档。
