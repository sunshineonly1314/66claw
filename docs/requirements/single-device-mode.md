# 单设备模式改造方案

**文档版本**: v1.3  
**创建日期**: 2026-02-04  
**最后更新**: 2026-02-04  
**状态**: ✅ 服务端已部署，客户端开发完成，可开始联调测试

---

## 1. 需求背景

产品决定将 OpenClawCN 授权改为**单设备模式**：

- 一个授权码只能在 **1 台设备** 上使用
- 用户可以随时切换设备，但需要**确认弹窗**
- 切换后有 **24 小时冷却期**，期间不能再次切换

---

## 2. 已确认的关键决策

| 决策项 | 结论 |
|--------|------|
| 新版本号 | **2026.2.0** |
| 被踢设备处理 | **方案 B**：必须等冷却期，不能自动重新绑定 |
| 冷却期计算基准 | 从**解绑时间**算起，全局生效 |
| `/devices/switch` 签名 | **不需要**强制签名 |
| 弹窗文案 | 使用"授权码"而非"账号" |

## 3. 服务端改动

### 3.1 新增错误码

| 错误码 | 常量名 | 含义 | 触发场景 |
|--------|--------|------|----------|
| **1010** | ERROR_DEVICE_SWITCH_REQUIRED | 需要确认设备切换 | 用户在新设备登录，已有其他设备绑定，且不在冷却期 |
| **1011** | ERROR_DEVICE_SWITCH_COOLDOWN | 设备切换冷却中 | 用户在 24 小时内尝试切换设备（包括被踢设备） |

### 3.2 新增接口

#### `POST /api/api/v1/license/devices/switch` - 确认设备切换

用户确认后调用，自动解绑旧设备并绑定新设备。

**请求参数**：

```json
{
  "key": "授权码",
  "deviceId": "新设备ID",
  "deviceName": "新设备名称（可选）",
  "osInfo": "操作系统信息（可选）",
  "appVersion": "2026.2.0"
}
```

> 注：签名参数（timestamp、nonce、sign）为可选，不强制要求。

**成功响应**（与 /verify 接口格式一致，使用 valid 字段）：

```json
{
  "code": 200,
  "data": {
    "valid": true,
    "license": {
      "tier": "basic",
      "tierName": "基础版",
      "expiresAt": "2026-12-31T23:59:59",
      "daysRemaining": 330,
      "keyType": "standard",
      "features": ["basic_chat", "basic_skills"]
    },
    "device": {
      "deviceId": "new-device-uuid",
      "deviceLimit": 1,
      "boundDevices": 1,
      "isCurrentBound": true
    }
  }
}
```

**失败响应**（冷却期内调用）：

```json
{
  "code": 200,
  "data": {
    "valid": false,
    "errorCode": 1011,
    "errorMessage": "设备切换冷却中，请 20 小时后再试",
    "device": {
      "cooldownRemainingHours": 20,
      "cooldownEndsAt": "2026-02-05T08:00:00"
    }
  }
}
```

### 3.3 验证接口响应格式变化

#### errorCode=1010 时的响应（需要确认切换）

```json
{
  "code": 200,
  "data": {
    "valid": false,
    "errorCode": 1010,
    "errorMessage": "检测到已在「我的电脑」上使用此密钥，继续将切换到当前设备",
    "device": {
      "existingDeviceId": "old-device-uuid",
      "existingDeviceName": "我的电脑",
      "existingOsInfo": "Windows 10 x64",
      "deviceLimit": 1,
      "boundDevices": 1
    }
  }
}
```

#### errorCode=1011 时的响应（冷却期）

```json
{
  "code": 200,
  "data": {
    "valid": false,
    "errorCode": 1011,
    "errorMessage": "设备切换冷却中，请 20 小时后再试",
    "device": {
      "cooldownRemainingHours": 20,
      "cooldownEndsAt": "2026-02-05T08:00:00"
    }
  }
}
```

### 3.4 版本兼容逻辑

服务端根据请求中的 `appVersion` 字段判断客户端版本：

| 客户端版本 | 服务端响应 |
|-----------|-----------|
| < 2026.2.0（旧版） | 返回 `errorCode=1004` + `errorMessage="设备数已达上限，请升级到最新版本"` |
| ≥ 2026.2.0（新版） | 返回 `errorCode=1010/1011` + 完整设备信息 |

### 3.5 被踢设备处理逻辑

**已确认采用方案 B**：被踢设备在冷却期内不能自动重新绑定。

```
被踢设备调用 /verify：
         ↓
检查：该授权码是否在 24 小时内有过设备切换？
  ├── 是 → 返回 errorCode=1011（冷却中）
  └── 否 → 返回 errorCode=1010（需确认切换）
```

服务端需要记录：
- `lastSwitchAt`：上次设备切换时间
- 用于判断是否在冷却期内

## 6. 完整交互流程

### 6.1 新设备首次绑定

```
用户在新设备打开客户端
         ↓
客户端调用 POST /verify（携带 appVersion: "2026.2.0"）
         ↓
服务端检查：该授权码是否已绑定设备？
         ↓
    无绑定设备 → 直接绑定，返回 valid=true
         ↓
客户端正常使用
```

### 6.2 新设备切换（已有绑定）

```
用户在新设备打开客户端
         ↓
客户端调用 POST /verify（携带 appVersion: "2026.2.0"）
         ↓
服务端检查：该授权码是否已绑定设备？
         ↓
    已有绑定 → 检查冷却期
         ↓
    ┌────────────────────────────────────┐
    │ 在冷却期内？                       │
    │   是 → 返回 errorCode=1011         │
    │   否 → 返回 errorCode=1010         │
    └────────────────────────────────────┘
         ↓
客户端收到 errorCode=1010 → 显示确认切换弹窗
         ↓
    ┌────────────────────────────────────┐
    │ 用户选择？                         │
    │   取消 → 关闭弹窗，保持未激活状态  │
    │   确认 → 调用 POST /devices/switch │
    └────────────────────────────────────┘
         ↓
服务端解绑旧设备，绑定新设备，记录切换时间
         ↓
返回 valid=true，客户端正常使用
         ↓
开始 24 小时冷却期
```

### 6.3 被踢设备再次打开

```
用户在被踢设备打开客户端
         ↓
客户端调用 POST /verify
         ↓
服务端检查：该设备未绑定，但授权码在冷却期内
         ↓
返回 errorCode=1011（冷却中）
         ↓
客户端显示冷却期弹窗
         ↓
用户点击「知道了」→ 弹窗关闭，无法使用
```

## 7. 边界情况处理

### 7.1 用户取消后再次打开

| 场景 | 处理 |
|------|------|
| 用户在确认弹窗点击「取消」 | 关闭弹窗，客户端保持未激活状态 |
| 用户再次打开应用 | 重新调用 /verify，再次显示确认弹窗 |

### 7.2 接口调用失败

| 场景 | 处理 |
|------|------|
| /verify 失败 | 显示网络错误提示，提供重试按钮 |
| /devices/switch 失败 | 显示"切换失败，请稍后重试"，保持弹窗可重试 |

### 7.3 网络超时

| 场景 | 处理 |
|------|------|
| 请求超时（>30s） | 显示"网络超时，请检查网络后重试" |

### 7.4 冷却期内切回旧设备

| 场景 | 处理 |
|------|------|
| 被踢设备在冷却期内打开 | 返回 1011，显示冷却期弹窗 |
| 被踢设备在冷却期后打开 | 返回 1010，显示确认切换弹窗 |
