## 一句话摘要

Memory 搜索管道中 `updatedAt` 字段从 SQL 到返回值全链路断裂，导致 `applyTimeTiering()` 冷热分层搜索完全失效；已修复管道并集成分层逻辑。

---

## 问题描述

### 用户视角

用户在使用 Memory 搜索时，应该优先看到最近更新的记忆（热数据），而不是被大量老旧记忆（冷数据）淹没。但实际上冷热分层搜索完全没有生效——所有记忆不分新旧、同等权重返回，导致：

1. **防遗忘失效**：最近的重要记忆可能被淹没在大量旧记忆中
2. **Token 浪费**：返回过多低价值的冷数据，浪费 LLM 上下文窗口
3. **搜索质量下降**：无法体现时间维度的相关性

### 技术背景

Memory 系统已实现三层架构：
- `chunks` 表有 `updated_at INTEGER NOT NULL` 列
- `search-tiering-cn.ts` 已实现 `applyTimeTiering()` 冷热分层函数（Hot 7d → Warm 30d → Cold 120d → Full fallback）
- 但搜索管道中间环节全部断裂

---

## 根因分析

### 断裂点 1: SQL 查询不 SELECT `updated_at`

**文件**: `src/memory/manager-search.ts`

`searchVector()` 的 SQL 只 SELECT 了 `id, path, start_line, end_line, text, source`，没有 `updated_at`。
`searchKeyword()` 原始 SQL 只从 FTS5 虚拟表查询，FTS5 本身不包含 `updated_at` 列。

### 断裂点 2: TypeScript 类型不包含 `updatedAt`

**文件**: `src/memory/manager-search.ts` + `src/memory/hybrid.ts`

- `SearchRowResult` 没有 `updatedAt` 字段
- `HybridVectorResult` / `HybridKeywordResult` 没有 `updatedAt` 字段
- `mergeHybridResults()` 的内部 Map 和返回类型都不包含 `updatedAt`

### 断裂点 3: `applyTimeTiering()` 未被调用

**文件**: `src/memory/manager.ts`

`search()` 方法的两个返回路径（vector-only 和 hybrid）都没有调用 `applyTimeTiering()`。函数已实现但完全未集成。

### 衍生问题: FTS5 JOIN sourceFilter 歧义

修复 `searchKeyword()` 添加 `JOIN chunks c ON c.id = f.id` 后，`sourceFilter.sql` 中无前缀的 `source` 列在 FTS5 表 `f` 和 chunks 表 `c` 之间产生歧义，导致关键字搜索返回 0 结果。

## 修改内容

### 1. manager-search.ts — SQL 查询 + 类型修复

| 改动点 | 说明 |
|--------|------|
| `SearchRowResult` 类型 | 增加 `updatedAt?: number` |
| `searchVector()` SQL | 增加 `c.updated_at` 到 SELECT，映射到 `updatedAt` |
| `listChunks()` SQL | 增加 `updated_at` 到 SELECT 和返回类型 |
| `searchKeyword()` SQL | JOIN chunks 表获取 `updated_at`：`FROM ftsTable f JOIN chunks c ON c.id = f.id` |
| `searchKeyword()` 映射 | 增加 `updatedAt: row.updated_at` |

### 2. hybrid.ts — 类型 + 合并逻辑修复

| 改动点 | 说明 |
|--------|------|
| `HybridVectorResult` 类型 | 增加 `updatedAt?: number` |
| `HybridKeywordResult` 类型 | 增加 `updatedAt?: number` |
| `mergeHybridResults()` Map | 内部类型增加 `updatedAt` |
| vector 映射 | `updatedAt: r.updatedAt` |
| keyword 合并 | 优先使用 keyword 的 `updatedAt`（可能更精确） |
| 返回值 | 包含 `updatedAt` |

### 3. manager.ts — 集成 applyTimeTiering + 修复 sourceFilter 歧义

| 改动点 | 说明 |
|--------|------|
| 新增 import | `import { applyTimeTiering } from "./search-tiering-cn.js"` |
| `mergeHybridResults()` | vector/keyword 映射增加 `updatedAt: r.updatedAt` |
| `search()` vector-only 路径 | 增加 `applyTimeTiering(vectorResults)` |
| `search()` hybrid 路径 | 增加 `applyTimeTiering(merged)` |
| `searchKeyword()` sourceFilter | 从 `this.buildSourceFilter()` 改为 `this.buildSourceFilter("f")`，消除 FTS5 JOIN 列名歧义 |

## 数据流修复前后对比

### 修复前（断裂）

```
chunks.updated_at (DB)
  → searchVector() SQL: ❌ 不 SELECT
  → searchKeyword() SQL: ❌ FTS5 无此列
  → SearchRowResult: ❌ 无 updatedAt 字段
  → HybridVectorResult/HybridKeywordResult: ❌ 无 updatedAt
  → mergeHybridResults(): ❌ 不保留
  → search() 返回: ❌ 无 updatedAt
  → applyTimeTiering(): ❌ 未调用
```

### 修复后（完整）

```
chunks.updated_at (DB)
  → searchVector() SQL: ✅ SELECT c.updated_at
  → searchKeyword() SQL: ✅ JOIN chunks c → SELECT c.updated_at
  → SearchRowResult: ✅ updatedAt?: number
  → HybridVectorResult/HybridKeywordResult: ✅ updatedAt?: number
  → mergeHybridResults(): ✅ 保留 + keyword 优先
  → search() 返回: ✅ updatedAt 传递
  → applyTimeTiering(): ✅ 两条路径都调用
    → Hot(7d) 优先 → Warm(30d) 补充 → Cold(120d) 兜底
```
