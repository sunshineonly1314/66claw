## 一句话摘要

Windows 安装包升级时强制杀进程可能导致 SQLite WAL 损坏造成用户"失忆"；新增优雅关闭机制 + 数据备份 + 删除有 P0 缺陷的在线安装包。

---

## 问题描述

### 用户视角

用户升级 OpenClawCN 后，发现 AI 助手"失忆"了——之前的对话记忆、会话历史、配置全部丢失，需要重新配置和训练。

### 技术背景

OpenClawCN 的记忆系统依赖多层存储：

| 层级 | 存储方式 | 数据目录 |
|------|----------|----------|
| 向量记忆（长期） | SQLite + 嵌入向量 | `{stateDir}/memory/` |
| 会话记录 | JSONL 文件 | `{stateDir}/sessions/` |
| 用户配置 | JSON 文件 | `{stateDir}/openclawcn.json` |
| 凭证/Token | JSON 文件 | `{stateDir}/credentials/` |

Windows 安装版的 `stateDir` = `{installDir}\data`。

---

## 根因分析

### P0: 在线安装包会删除用户全部数据

**文件**: `scripts/windows/setup-online.iss`（已删除）

```ini
; 第 145 行 — 卸载时删除 data 目录
[UninstallDelete]
Type: filesandordirs; Name: "{app}\data"
```

同时，该文件的 `[Dirs]` 区块缺少 `uninsneveruninstall` 标志。用户卸载在线版时，所有记忆、会话、配置会被彻底删除。

### P2: 升级时强制杀进程导致 SQLite WAL 损坏

**文件**: `scripts/windows/setup.iss` (修复前)

原始的 `CurStepChanged(ssInstall)` 直接执行 `taskkill /f` 强制杀死所有进程。`Process.Kill()` 在 Windows 上等同于 `TerminateProcess()`——进程被立即终止，无法执行任何清理代码。

如果此时 SQLite 的 WAL (Write-Ahead Logging) 正在写入：
- WAL 文件可能被截断
- checkpoint 无法完成
- 下次启动时数据库可能损坏或丢失最近写入

### P2: OpenClawCNService.exe 的 StopGatewayInternal() 也是强杀

原始的 `StopGatewayInternal()` 直接调用 `gatewayProcess.Kill()`。Node.js 在 Windows 上无法捕获来自 `TerminateProcess()` 的信号（不像 Unix 的 SIGTERM），因此无法执行优雅关闭。

### P3: 无数据备份机制

升级前没有任何备份步骤。一旦数据损坏，无法恢复。

### 竞态条件: Watchdog 重启竞态

**发现于边界条件分析阶段**

OpenClawCNService.exe 托盘进程内置 Watchdog 定时器（15秒间隔），会在检测到 Gateway 不在运行时自动重启它。在优雅关闭 Gateway 后、force-kill 执行前，Watchdog 可能检测到 Gateway 已停止并重新启动一个新的 Gateway 进程，导致新 Gateway 被 force-kill 终止——这恰好是我们试图避免的场景。

## 修改内容

### 1. 删除在线安装包 (P0)

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `scripts/windows/setup-online.iss` | **删除** | 消除 P0 数据删除风险，以后仅保留离线版 |

### 2. 新增 HTTP 优雅关闭端点 (P2)

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `src/gateway/server-http.ts` | 修改 | 新增 `setGatewayShutdownHandler` 模块级 late-binding + `POST /api/shutdown` 端点 |
| `src/gateway/server.impl.ts` | 修改 | 导入 `setGatewayShutdownHandler`，提取 `fullClose` 并绑定 |

#### `/api/shutdown` 端点设计

```
POST /api/shutdown
Authorization: Bearer <token>

安全层:
├─ 仅 POST 方法 (405)
├─ 仅 localhost 访问 (403) — 检查 127.0.0.1 / ::1 / ::ffff:127.0.0.1
├─ Bearer Token 认证 (401) — 匹配 OPENCLAWCN_GATEWAY_TOKEN
├─ Handler 未就绪检查 (503)
└─ 防双击 — capture-and-null 模式

响应: { ok: true, message: "shutting down" }
100ms 后触发 fullClose() → server-close.ts 完整关闭链
```

#### Late-binding 模式

close handler 在 HTTP server 之后创建（`server.impl.ts` 的 `createGatewayServer()` 末尾），但 `/api/shutdown` 路由在 HTTP server 创建时就注册了（`server-http.ts` 的 `createGatewayHttpServer()`）。通过模块级 setter 解决鸡生蛋问题：

```typescript
// server-http.ts
let _shutdownFn: ((opts?: { reason?: string }) => Promise<void>) | null = null;
export function setGatewayShutdownHandler(fn) { _shutdownFn = fn; }

// server.impl.ts (在 close handler 创建后)
setGatewayShutdownHandler(fullClose);
```

### 3. OpenClawCNService.exe 优雅关闭改造 (P2)

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `scripts/windows/native/OpenClawCNService.cs` | 修改 | 新增 `stop` CLI 命令 + `KillOtherOpenClawCNServiceInstances` + `TryGracefulShutdownStatic/Http` + 重写 `StopGatewayInternal` |

#### 新增 `stop` CLI 命令

在 `Main()` 的 Mutex 之前处理，不需要获取单实例锁：

```csharp
if (args[0] == "stop")
{
    KillOtherOpenClawCNServiceInstances();  // 消灭 Watchdog
    TryGracefulShutdownStatic(18789, "openclawcn2026");  // HTTP 优雅关闭
    Environment.Exit(exitCode);
}
```

#### Watchdog 竞态修复

```csharp
static void KillOtherOpenClawCNServiceInstances()
{
    int myPid = Process.GetCurrentProcess().Id;
    foreach (var proc in Process.GetProcessesByName("OpenClawCNService"))
        if (proc.Id != myPid)
            proc.Kill();  // TerminateProcess — 立即终止，Watchdog 无法再触发
    Thread.Sleep(500);
}
```

**关键原理**: `Process.Kill()` → Win32 `TerminateProcess()` 是同步的，立即终止进程内所有线程。Watchdog 的 `System.Windows.Forms.Timer` 基于 Windows 消息泵，进程终止后消息无法被分发。**竞态窗口 = 0ms**。

#### 重写 `StopGatewayInternal()`

```
StopGatewayInternal:
├─ Step 1: TryGracefulShutdownHttp()
│   ├─ POST /api/shutdown + Bearer token
│   ├─ 成功 → WaitForExit(8s) → 干净退出 ✅
│   └─ 失败 → 继续 fallback
├─ Step 2: gatewayProcess.Kill() (force kill)
├─ Step 3: KillProcessOnPort(port)
└─ Step 4: CleanLockFile()
```

### 4. 安装包升级流程改造 (P3 + P2)

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `scripts/windows/setup.iss` | 修改 | 重写 `CurStepChanged(ssInstall)`：4步安全升级流程 |

#### 新升级流程

```
CurStepChanged(ssInstall):
│
├─ Step 1: xcopy 备份 data → data.backup
│   使用 xcopy /E /I /H /Y 复制全部文件（含隐藏文件）
│   先删除旧 data.backup（仅保留一份滚动备份）
│
├─ Step 2: OpenClawCNService.exe stop
│   ├─ KillOtherOpenClawCNServiceInstances() — 消灭 Watchdog
│   └─ TryGracefulShutdownStatic() — HTTP 优雅关闭 Gateway
│       └─ 等待端口释放（最多 10 秒）
│
├─ Step 3: taskkill + wmic (纯防御兜底)
│   ├─ taskkill /f /im OpenClawCNService.exe
│   └─ wmic kill node.exe (按 cmdline 过滤 OpenClawCN/openclawcn)
│
└─ Step 4: Sleep(500ms) — 确保进程完全退出
```

```

      → server-http.ts /api/shutdown handler
        → 验证: POST + localhost + Bearer token
        → capture-and-null 防双击
        → res.end(200)

          → fullClose()  [server.impl.ts]
            → stopDiagnosticHeartbeat
            → clearTimeout(skillsRefreshTimer)
            → skillsChangeUnsub()
            → close()  [server-close.ts]
              → stop Bonjour/Tailscale/Canvas
              → stop channel plugins
              → stop plugin services
              → stop Gmail watcher
              → stop license/security services
              → stop cron/heartbeat
              → broadcast "shutdown" to WebSocket clients
              → clear intervals
              → close all WebSocket connections
              → stop config reloader
              → wss.close()

              → httpServer.close()

```
