## 一、背景与问题

### 1.1 当前状态

| 平台 | Gateway 运行方式 | 用户体验 |
|-----|----------------|---------|
| macOS | Menubar App，系统托盘运行 | ✅ 静默后台，用户无感 |
| Linux | systemd 服务 | ✅ 静默后台，用户无感 |
| **Windows** | **终端窗口运行** | ❌ 关闭窗口即停止服务 |

### 1.2 用户反馈

Windows 用户反馈的核心问题：

1. **"我关掉那个黑窗口，OpenClawCN 就不能用了"**
2. **"每次开机都要手动启动，太麻烦了"**
3. **"那个窗口一直开着很碍眼"**
4. **"不知道 Gateway 有没有在运行"**

### 1.3 影响范围

- 所有 Windows 10/11 用户
- 预估占比：用户总量的 40-50%

## 二、用户场景

### 场景 1：首次安装启动

**用户**：小白用户，刚安装完 OpenClawCN

**当前体验**：
1. 按照文档在终端输入 `openclawcn gateway run`
2. 看到一个黑色窗口，不知道该怎么办
3. 以为启动完成，关闭窗口
4. 打开 Web UI，发现连不上
5. 困惑、求助

**期望体验**：
1. 安装完成后，Gateway 自动启动
2. 用户无需关心 Gateway 是什么
3. 直接使用 Web UI 或其他功能

---

### 场景 2：日常使用

**用户**：已熟悉 OpenClawCN 的用户

**当前体验**：
1. 每天开机后手动启动 Gateway
2. 保持终端窗口打开，不敢关闭
3. 窗口占用任务栏位置
4. 偶尔误关窗口，服务中断

**期望体验**：
1. 开机自动启动，无需手动操作
2. 后台静默运行，不占用任务栏
3. 需要时能快速查看状态、控制服务

---

### 场景 3：状态感知

**用户**：正在使用 OpenClawCN 的用户

**当前体验**：
1. Web UI 突然连不上
2. 不知道是网络问题还是 Gateway 停了
3. 打开终端检查，发现窗口被关了
4. 重新启动

**期望体验**：
1. 能直观看到 Gateway 运行状态
2. 服务异常时有明确提示
3. 可以一键重启

---

### 场景 4：故障恢复

**用户**：Gateway 因某种原因崩溃

**当前体验**：
1. 用户不知道服务已停止
2. 功能异常时才发现
3. 手动重新启动

**期望体验**：
1. 服务崩溃后自动重启
2. 或者至少有明确通知
3. 提供快速恢复手段

## 四、用户体验要求

### 4.1 无感知原则

- 普通用户不需要知道"Gateway"是什么
- 安装即用，无需额外配置
- 后台服务对用户透明

### 4.2 状态可见原则

- 需要时，用户能快速确认服务状态
- 异常情况有明确提示
- 不打扰正常使用

### 4.3 操作简便原则

- 常用操作一步完成（启动/停止/重启）
- 避免需要打开终端输入命令
- 与 macOS 版本体验对齐

### 4.4 资源友好原则

- 后台运行时资源占用尽可能低
- 不显著增加系统启动时间
- 不显著增加安装包体积

## 六、与现有功能的关系

### 6.1 命令行方式保留

- 现有 `openclawcn gateway run` 命令继续保留
- 高级用户仍可选择终端方式运行
- 两种方式不应同时运行（需互斥检测）

### 6.2 端口冲突智能处理

启动前必须检测端口 18789 占用情况，并根据不同场景提供**一键解决方案**：

#### 场景 A：OpenClawCN 已在运行

| 检测条件 | 处理方式 |
|---------|---------|
| 端口被占用 + 进程命令行包含 "gateway" | 判定为 OpenClawCN 实例 |

**用户交互**：
```
[提示] OpenClawCN 服务已在运行中!

进程 ID: 12345
Web 控制台: http://localhost:18789

是否要重启服务？
[Y] 重启服务  [N] 保持现状并退出
```

- 用户选 Y → 自动停止旧进程，启动新实例
- 用户选 N → 直接退出，不做任何操作

#### 场景 B：端口被其他程序占用

| 检测条件 | 处理方式 |
|---------|---------|
| 端口被占用 + 非 OpenClawCN 进程 | 判定为端口冲突 |

**用户交互**：
```
[错误] 端口 18789 已被其他程序占用!

占用进程: someapp.exe (PID: 6789)

是否要结束该进程以释放端口？
[Y] 结束进程并继续  [N] 退出
```

- 用户选 Y → 自动结束占用进程，继续启动
- 用户选 N → 退出，用户自行处理

#### 设计原则

1. **小白友好**：用户无需知道什么是 PID、端口、任务管理器
2. **一键解决**：输入 Y 即可自动处理，无需额外操作
3. **安全确认**：结束进程前必须用户确认，避免误杀重要程序
4. **信息透明**：显示占用进程名称，让用户知道将要结束什么

### 6.2 与 Web UI 的配合

- Web UI 应能检测 Gateway 连接状态
- 连接失败时，提供明确提示和解决指引
- 可考虑在 Web UI 中提供启动 Gateway 的入口

### 6.3 与 macOS/Linux 版本的一致性

- 功能范围与 macOS Menubar App 对齐
- 用户操作习惯保持一致
- 状态显示方式保持一致
