## 文档信息

| 项目 | 内容 |
|------|------|
| **版本** | v4.1 |
| **日期** | 2026-02-17 |
| **负责人** | 产品经理 + UI/UX设计师 + 技术专家 |

| **目标用户** | 中国本土用户（小白为主，兼顾懂行用户） |

## 1. 背景与问题

### 1.1 现状

OpenClawCN当前UI继承自OpenClaw开源项目，存在以下严重问题：

| 问题 | 现状 | 影响 |
|------|------|------|
| 页面过多 | 17个页面，4个分组 | 用户不知道从哪开始 |
| 信息过载 | Config页23个配置section，300+状态变量 | 分析瘫痪，用户放弃 |
| 定位不清 | 像运维控制台，不像AI聊天工具 | 用户心智错位 |
| 概念暴露 | Skills/MCP/Extensions/Playground分散4个页面 | 用户分不清区别 |
| 国际化痕迹重 | 默认展示需要外网的Skills和渠道 | 国内用户无法使用 |
| 空状态无引导 | 功能未配置时显示空白 | 用户不知道下一步做什么 |

### 1.2 目标

- **50秒开箱即用**：从首次打开到第一次AI对话 <=50秒
- **Chat为王**：90%的用户时间在对话页，其他页面是辅助
- **17页 -> 7页**：砍掉60%页面，合并同类功能
- **JIT配置**：未配置的功能在用到时引导，而非提前全部配置
- **本土化优先**：默认只展示国内可用的内容

### 1.3 商业约束

- OpenClawCN是MIT项目的中国本土化深度定制版，需要用户购买激活码
- 没有平台提供的免费模型，但蚂蚁百灵和美团LongCat有每日免费额度
- 激活码验证是商业命脉，必须优先处理

## 2. 开箱引导流程

### 2.1 流程总览

```
Step 1          Step 2          Step 3          Step 4
激活+协议  ---->  配置AI服务  ---->  需求画像  ---->  进入对话
(10秒)          (5-30秒)        (10秒/可跳过)   (即时)
```

**总耗时：25-50秒**

### 2.2 Step 1：激活 + 协议

**目的**：确认付费身份 + 法律合规

**页面内容**：
1. 品牌标语："OpenClawCN -- 你的AI智能引擎"
2. 激活码输入框（页面主体，最大最醒目）
3. 扫码激活入口（微信扫码，与输入框并列）
4. 协议勾选区：
   - 3行风险要点（AI会犯错 / 数据发给服务商 / 操作前征同意）
   - 勾选"我已阅读并同意《用户服务协议》和《隐私政策》"
5. 「激活并开始」按钮

**交互逻辑**：
- 激活码输入支持粘贴自动识别格式
- 扫码后后台轮询激活状态，成功自动跳转
- 必须勾选协议才能点击激活按钮
- 激活失败显示错误原因+重试

**技术对接**：
- 后端：`src/license/` 激活码校验、设备绑定
- 前端：`ui/src/ui/license/` 激活组件
- 协议文档：`docs/legal/用户服务协议.md`、`docs/legal/隐私政策.md`

### 2.3 Step 2：配置AI服务

**目的**：让AI引擎能运行

**页面分两个区域**：

#### 区域A：免费体验（推荐，页面上方）
- 展示蚂蚁百灵 + 美团LongCat两个免费服务
- 说明：每日50万Token免费额度，两家合计约100万Token/天
- 「一键启用」按钮，系统预置Key，零配置
- 额度用完自动停，不产生费用

#### 区域B：自有AI服务（页面下方）
- 国内服务商列表（默认展示）：
  - DeepSeek / 通义千问 / 智谱GLM / Kimi / 豆包 / 腾讯混元 / MiniMax等
  - 每个服务商：Logo + 名字 + 一句话特色
- 选中服务商 -> 粘贴API Key -> 自动验证
- "去哪获取？"可展开图文指引（带截图+跳转链接）
- 底部折叠区："国际服务（需国际网络）" / "本地模型（Ollama等）"

#### 两个区域的关系
- 可以只用免费的，可以只用自有的，也可以都配
- 都配了的情况：免费额度用完自动切到自有服务
- 免费服务作为兜底，降低弃用率

**交互逻辑**：
- 国际服务区域：自动检测网络可达性，不通则灰掉+提示
- API Key粘贴后即时验证，显示验证结果+可用模型+余额
- 验证通过后「下一步」按钮亮起

**技术对接**：
- 服务商列表：`src/agents/models-config.providers.ts`
- 免费模型：`src/config/free-model-providers.ts`
- CN地区排名：`src/config/region-cn.ts`
- API验证：现有setup-wizard-handlers中的验证逻辑

### 2.4 Step 3：需求画像

**目的**：根据用户需求智能预装Skills，而非使用官方默认配置

**页面内容**：
- 说明："你平时会用AI做什么？选几个，我们帮你装好对应的技能"
- 10个可多选标签：

| 标签 | 自动安装的Skills |
|------|----------------|
| 写文档/邮件 | markdown编辑, 模板生成 |
| 搜索查资料 | 百度搜索, 知乎搜索 |
| 翻译 | 多语言翻译 |
| 读PDF/论文 | PDF阅读器, 文档总结 |
| 写代码 | 代码助手, Gitee集成 |
| 数据分析 | 表格处理, 图表生成 |
| 图片生成 | 通义万相/SeedDream（需额外API，安装后JIT配置） |
| 日程/提醒 | 定时任务, 日历提醒 |
| 微信/钉钉/飞书 | 对应渠道插件（标记为"待连接"，进入后JIT配置） |
| 新闻/资讯 | 百度搜索, RSS摘要 |

- 底部："跳过，以后再说"链接

**交互逻辑**：
- 选完点"完成" -> 后台静默安装（国内镜像加速），不阻塞进入主界面
- 硬性需求Skills（系统必需）始终安装，不受用户选择影响
- 需要国际网络的Skills不出现在选项中
- 需要额外API Key的Skills先装好，用的时候JIT引导配置
- Chat页的快捷指令栏根据选择动态生成

**技术对接**：
- Skills安装：`src/agents/skills/` + skills-batch系统
- CN镜像：`src/config/cn-mirrors.ts`
- Skills分类：`src/agents/skills/skills-manifest.ts`

### 2.5 Step 4：进入对话页

- 根据Step 3选择，对话区预设动态示例：
  - 选了"写文档" -> "帮我写一封请假邮件"
  - 选了"翻译" -> "把这段话翻译成英文"
  - 选了"搜索" -> "帮我查一下最新的AI新闻"
- 用户点击示例或自己打字 -> 立即得到回复
- 第一次"价值体验"在这里发生

## 4. 各页面详细设计

### 4.1 Chat页（主页）

**设计原则**：对标豆包/GPT/Gemini，去掉一切运维控制台气息

#### 顶栏

| 元素 | 位置 | 功能 |
|------|------|------|
| 对话标题 | 左侧 | 显示当前对话名，可点击编辑 |
| 模型切换 | 右侧 | 下拉选择，显示当前模型名 |

**模型切换下拉结构**：
```
当前: DeepSeek V3  (下拉)
---
免费模型
   蚂蚁百灵 (剩余48万Token)
   美团LongCat (剩余50万Token)
---
已配置
   DeepSeek V3
   通义千问 Max
---
+ 添加新的AI服务
```

#### 消息区

- 干净的对话气泡流
- AI调用工具/技能时：折叠显示"已使用 百度搜索"，点击展开详情
- 图片结果内联显示，点击放大（复用现有image-lightbox）
- compaction在后台静默运行，不展示indicator
- voice mascot只在语音输入激活时出现

#### 输入区

```
+--------------------------------------------------+
|  [写文档]  [搜索]  [翻译]  [+ 更多]                |  <-- 快捷指令栏
+--------------------------------------------------+
|                                                  |
|  [附件]  输入消息...                       [发送]  |
|                                                  |
+--------------------------------------------------+
```

**快捷指令栏**：
- 根据Step 3需求画像动态显示3-4个常用操作
- 点击自动填入提示词模板，光标定位在填空处
- 「+ 更多」展开所有可用快捷指令
- **这是核心的能力发现机制** -- 用户每次看到就被提醒AI还能做什么

**附件按钮**：支持图片/文件上传 + 拖拽上传

#### 砍掉的元素

| 现有元素 | 处理 | 原因 |
|---------|------|------|
| session选择器 | 砍掉 | 对话列表已在左侧 |
| focus mode toggle | 移入设置-高级 | 高级功能 |
| compaction indicator | 隐藏 | 后台运行，用户不需要知道 |
| welcome discovery wizard | 砍掉 | Step 3需求画像替代 |
| voice mascot常驻显示 | 改为仅激活时显示 | 减少视觉噪音 |
| trial user banner | 砍掉 | Step 1已完成激活 |

#### JIT触发场景

| 触发条件 | 弹出内容 |
|---------|---------|
| 发消息但AI服务未配/过期 | 引导配置AI服务 |
| 发图片但模型不支持视觉 | 提示切换支持视觉的模型 |
| AI回复提及某技能但未安装 | 提示安装该技能 |
| 免费额度用尽且无自有服务 | 引导配置自有AI服务 |

**设计原则**：一屏看完所有状态，不深挖数据

**合并来源**：Overview + Usage + Free Models

#### 3个卡片

**卡片1：AI服务状态**
- 当前主力模型 + 运行状态（正常/异常）
- 免费额度：今日已用 / 总额度，进度条
- 自有服务余额（如果配了）
- 异常时显示红色状态 + "修复"按钮

**卡片2：今日使用**
- 对话次数
- 使用字数（万字为单位）
- 最近7天柱状趋势图（简单，无日期选择器）

**卡片3：系统状态**
- 激活状态 + 有效期
- 已连接渠道数（可点击跳转连接页）

- 「一键体检」按钮 -> 运行Doctor检查，结果以绿/黄/红展示

#### 砍掉的内容

| 原内容 | 处理 |
|-------|------|
| Session详细列表 | 移入设置-高级 |
| 按模型/provider的cost breakdown | 移入设置-高级 |
| Query builder | 移入设置-高级 |

- 钉钉

### 4.4 技能页

**设计原则**：三页合一，像应用商店

**合并来源**：Skills + Extensions + Playground

#### 3个Tab

**Tab 1：推荐（默认）**
- 根据Step 3需求画像 + 使用行为智能推荐10-15个技能
- 首次根据需求画像生成；后续根据对话行为动态调整
- 例：用户多次问天气 -> 推荐天气查询技能

**Tab 2：分类浏览**
- 6个分类：办公 / 搜索 / 创作 / 沟通 / 生活 / 开发
- 每个分类下展示该类别的技能列表

**Tab 3：已安装**
- 当前已装的技能列表
- 可启用/禁用/卸载

#### 技能卡片统一格式
```
[图标]  技能名称
        一句话说明
        [已安装] 或 [安装] 或 [需配置]
```

#### 安装流程
1. 点「安装」-> 后台国内镜像下载，显示进度
2. 不需额外配置的 -> 直接变为"已安装"
3. 需要额外API的 -> 状态变"需配置"，不强制立即配
4. 实际使用时 -> JIT弹出配置引导

#### 本土化策略

| 策略 | 实现 |
|------|------|
| 默认隐藏国际技能 | 设置中"显示国际技能"开关，默认关闭 |
| 国内技能优先排序 | 推荐和分类中国内技能排前 |
| 国内镜像加速 | 安装时用淘宝/腾讯/中科大镜像 |
| 国际技能标注 | 打开开关后，带"需国际网络"标签 |

#### 砍掉的内容
- Playground独立页面 -> 合并为推荐Tab
- Extensions独立页面 -> 合并进来
- bundled/workspace/managed分组 -> 用户不关心来源
- MCP和Skills概念区分 -> 统一叫"技能"

## 5. JIT（Just-In-Time）配置机制

### 5.1 设计原则

> 用户没碰的功能不要提前配置。在用户实际触发时，当场引导完成配置。

### 5.2 弹出格式

统一为当前页面内的**卡片式引导**（不是全屏跳转、不是弹窗）：
```
+----------------------------------------+
| [图标]  标题：缺少XX配置                 |
|                                        |
| 一句话说明为什么需要这个配置              |
|                                        |
| [去配置]              [以后再说]         |
+----------------------------------------+
```

### 5.3 触发场景清单

| 序号 | 触发动作 | 检测条件 | 引导内容 |
|------|---------|---------|---------|
| J1 | 发送对话消息 | AI服务未配置或Key过期 | 引导配置AI服务 |
| J2 | 发送图片 | 当前模型不支持视觉 | 提示切换支持视觉的模型 |
| J3 | 使用某个Skill | 该Skill未安装 | 引导安装 |
| J4 | 使用已安装的Skill | 该Skill需要额外API | 引导配置对应API Key |
| J5 | 点击连接某渠道 | 渠道未配置 | 进入该渠道的分步配置 |
| J6 | 请求图片生成 | 图片生成服务未配 | 引导配置DashScope/SiliconFlow等 |
| J7 | 免费额度用尽 | 无自有AI服务 | 引导配置自有服务或等次日额度重置 |
| J8 | 尝试使用国际Skill | 国际网络不通 | 提示"此技能需国际网络" |
| J9 | AI建议使用某能力 | 对应技能未安装 | AI回复中自然带出安装建议 |

### 5.4 行为规范
- JIT检测在功能入口处进行，不是全局轮询
- 用户点"以后再说"后，同一JIT在本次session内不再弹出
- 配置完成后自动重试用户原始操作（如：配完API Key后自动重发消息）

## 6. 本土化策略

### 6.1 Skills本土化

| 策略 | 详细说明 |
|------|---------|
| 默认只展示国内Skills | 设置中"显示国际技能"开关控制 |
| 国内替代优先 | Google搜索 -> 百度搜索，GitHub -> Gitee |
| 安装源替换 | npm -> 淘宝镜像，pip -> 清华镜像，go -> 七牛镜像 |
| CN专属Skills优先推荐 | 百度搜索、高德交通、通义万相绘图、Edge TTS等 |

### 6.2 网络环境检测

- 开箱Step 2自动检测国际网络可达性
- 检测结果存储在本地配置，影响：
  - 国际AI服务商列表是否可选
  - 国际Skills/MCP是否显示
  - 国际渠道是否展示
- 用户可在设置中手动开关"显示国际内容"

### 6.3 服务商展示策略

| 网络环境 | 服务商展示 |
|---------|----------|
| 仅国内网络（默认） | 只展示国内服务商 + 免费模型 |
| 有国际网络（手动开启） | 国内优先展示 + 国际服务折叠显示 + 跨境数据提醒 |

## 9. 技术实现建议

### 9.1 路由结构

```
/chat                -> Chat页（默认）
/dashboard           -> 看板页
/channels            -> 连接页
/channels/:id/setup  -> 渠道配置引导
/skills              -> 技能页
/skills?tab=recommend|browse|installed
/agents              -> Agent页
/agents/:id          -> Agent详情
/cron                -> 定时页
/settings            -> 设置页
/settings/advanced   -> 设置-高级选项
/setup               -> 开箱引导流程
```

### 9.2 状态管理优化

现有`app.ts`有300+状态变量在一个组件中，建议按域拆分Controller：
- ChatController：对话相关
- ConfigController：配置相关
- LicenseController：激活相关
- SkillsController：技能相关
- ChannelController：渠道相关

### 9.3 兼容性

- 所有高级功能不删除代码，只是UI层隐藏
- 高级选项展开后功能完整保留
- URL直接访问高级功能仍然可用

### 9.4 JIT组件

**统一组件**：`<jit-config-guide>`
- 接收type参数：ai-service / skill-install / skill-api / channel / vision / image-gen / network
- 卡片形式嵌入当前页面
- 配置完成后emit事件，触发原始操作重试
