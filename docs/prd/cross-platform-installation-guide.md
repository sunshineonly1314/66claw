## 一、设计原则

### 1.1 核心理念

| 原则 | 说明 |
|-----|------|
| **一键安装** | 下载 → 双击 → 完成，不超过 3 步 |
| **零黑窗口** | 全程 GUI 进度条，用户看不到 cmd/PowerShell |
| **小白友好** | 所有提示使用通俗中文，无技术术语 |
| **故障自愈** | 安装失败自动重试，提供明确指引 |

### 1.2 功能目标

用户安装完成后，应能使用以下 Skills：

| Skill 类别 | 功能示例 |
|-----------|---------|
| 浏览器控制 | 打开浏览器、搜索内容、截图网页 |
| 应用启动 | 打开记事本、计算器、微信等 |
| 文件操作 | 创建/读取/搜索文件 |
| 系统信息 | 查看 CPU/内存/磁盘状态 |
| 终端命令 | 执行系统命令（高级用户） |

## 三、Windows 安装方案（重点）

### 3.1 技术选型：WSL2

**为什么选择 WSL2？**

| 方案 | Skills 支持 | 安装复杂度 | 小白友好度 |
|-----|------------|-----------|-----------|
| 纯 Windows Node.js | ⚠️ 有限 | 简单 | ⭐⭐⭐⭐ |
| Docker Desktop | ✅ 完整 | 中等 | ⭐⭐⭐ |
| **WSL2** | ✅ 完整 | 中等 | ⭐⭐⭐⭐ |
| 虚拟机 | ✅ 完整 | 复杂 | ⭐ |

**WSL2 优势**：
- 完整 Linux 环境，所有 Skills 都能运行
- 与 Windows 深度集成，可调用 Windows 应用
- 微软官方支持，稳定可靠
- 资源占用比虚拟机低

```powershell
# 检测当前是否以管理员身份运行
$isAdmin = ([Security.Principal.WindowsPrincipal] [Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)

if (-not $isAdmin) {
    return "NOT_ADMIN"
}
```

```csharp
// C# 检测管理员权限
public static bool IsRunAsAdmin()
{
    WindowsIdentity identity = WindowsIdentity.GetCurrent();
    WindowsPrincipal principal = new WindowsPrincipal(identity);
    return principal.IsInRole(WindowsBuiltInRole.Administrator);
}
```

#### 3.2.5 虚拟化检测代码

```powershell
# 检测虚拟化是否开启（后台执行，用户看不到）
$vmInfo = Get-WmiObject -Class Win32_ComputerSystem
$hypervisorPresent = (Get-WmiObject -Class Win32_ComputerSystem).HypervisorPresent
$vmFirmwareEnabled = (Get-CimInstance -ClassName Win32_Processor).VirtualizationFirmwareEnabled

if ($vmFirmwareEnabled -eq $true) {
    # 虚拟化已开启，继续安装
    return "OK"
} else {
    # 虚拟化未开启，阻断安装
    return "BLOCKED"
}
```

#### 3.2.6 不支持虚拟化的情况

| 情况 | 说明 | 处理方式 |
|-----|------|---------|
| 老旧 CPU | 2010 年前的 CPU 可能不支持 | 显示提示，建议升级电脑 |
| BIOS 无选项 | 部分品牌机锁死了选项 | 提供品牌机特定教程链接 |
| 已被占用 | 其他虚拟化软件占用（如 VMware） | 提示关闭其他虚拟化软件 |

**Windows 家庭版**：✅ 支持 WSL2（Windows 10 2004+ 开始支持）

### 3.4 后台安装步骤（用户不可见）

> ⚠️ **重要：以下标注了需要特殊处理的步骤，确保用户不会看到黑窗口或卡住**

```
阶段 0: 权限检查 (启动时立即执行)
└── 检查管理员权限 ← 未通过则阻断，提示用户重新以管理员身份运行

阶段 1: 环境检查 (0-10%)
├── 检查 Windows 版本（需要 Win10 2004+ 或 Win11）
├── 检查系统架构 (仅支持 x64)
├── 检查虚拟化状态 ← 未通过则阻断，显示 BIOS 教程
├── 检查磁盘空间 (需要 3GB 可用空间)
├── 检查是否有损坏的 WSL 安装 ← 有则提供修复选项
└── 检查网络连通性（测试镜像可达）

阶段 2: WSL2 功能启用 (10-30%) ⚠️ 【可能需要重启电脑！】
├── 检查 WSL 是否已启用
├── 如未启用：
│   ├── 启用 WSL 功能 (dism.exe /online /enable-feature)
│   ├── 启用虚拟机平台 (dism.exe /online /enable-feature)
│   ├── 【关键】显示重启提示页面（见 3.4.1）
│   ├── 【关键】写入"安装未完成"标记到注册表
│   ├── 用户点击重启 → 电脑重启
│   └── 重启后自动继续安装（通过 RunOnce 注册表）
├── 如已启用：跳过重启，继续
└── 设置 WSL 默认版本为 2

阶段 3: Ubuntu 环境部署 (30-60%) 【使用预配置镜像，无黑窗口！】
├── 【本地解压】从安装包解压预配置 Ubuntu 镜像 (~250MB 压缩)
├── 【静默导入】wsl --import（完全无窗口）
├── 【配置】设置默认用户为 openclawcn
└── 【验证】测试 WSL 可正常执行命令

阶段 4: Playwright 下载 (60-80%) 【唯一需要下载的大文件】
├── 【下载】从 npmmirror 下载 Playwright Chromium (~280MB)
├── 显示下载进度 + 速度 + 剩余时间
├── 支持断点续传
└── 下载失败自动切换备用镜像

阶段 5: OpenClawCN 安装 (80-90%) 【从安装包解压，无需下载】
├── 【本地】解压 OpenClawCN 包（已打包在安装程序中）
├── 【本地】安装项目自带 Skills
├── 【配置】在 WSL 内配置 npm 镜像
└── 【配置】配置环境变量和路径

阶段 6: 集成配置 (90-98%)
├── 【本地】创建 Windows 托盘应用（已打包在安装程序中）
├── 配置开机自启动（用户级注册表）
├── 创建桌面快捷方式
├── 创建开始菜单快捷方式
├── 注册任务计划程序（健康检查）
└── 添加防火墙规则

阶段 7: 完成 (98-100%)
├── 启动 Gateway 服务
├── 验证服务状态（检查端口、进程）
├── 如端口被占用 → 尝试其他端口或提示用户
└── 打开 Web UI
```

**技术实现**：

```csharp
// 1. 写入 RunOnce 注册表，确保重启后自动继续
Registry.SetValue(
    @"HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\RunOnce",
    "OpenClawCNSetupContinue",
    $"\"{installerPath}\" --continue-install"
);

// 2. 写入安装状态，记录当前进度
Registry.SetValue(
    @"HKEY_CURRENT_USER\Software\OpenClawCN\Setup",
    "InstallStage",
    "WSL_ENABLED_PENDING_REBOOT"
);

// 3. 提示用户重启
// 用户点击"立即重启"后执行：
Process.Start("shutdown", "/r /t 5 /c \"OpenClawCN 安装需要重启电脑\"");
```

### 3.4.2 Ubuntu 镜像方案选择（关键决策！）

> ⚠️ **关键问题**：标准 Ubuntu WSL 首次运行会弹出终端窗口要求创建用户名密码

#### 方案对比

| 方案 | 说明 | 安装包大小 | 黑窗口？ | 推荐 |
|-----|------|-----------|---------|------|
| ❌ 方案A：下载标准镜像 | 从阿里云下载官方 tar.gz | 小（下载400MB） | **有！要输入用户名密码** | ❌ |
| ✅ **方案B：预配置镜像打包** | 打包我们预配置好的镜像 | 大（+250MB压缩） | **无！** | ✅ |

#### 🚨 重要：必须使用方案B！

**原因**：
1. 方案A（标准镜像）首次启动**必定**弹出黑窗口要求创建用户
2. 方案C（脚本配置）需要 WSL 已启动，但启动时就会要求创建用户，形成死循环
3. **只有方案B（预配置镜像）能真正避免黑窗口**

#### 方案B 实现：预配置镜像

**开发时制作预配置镜像**：

```bash
# 1. 在开发机上创建标准 Ubuntu WSL
wsl --install -d Ubuntu-22.04

# 2. 完成初始化（输入用户名 openclawcn，设置密码）
# 用户名: openclawcn
# 密码: openclawcn（或其他默认密码）

# 3. 配置国内镜像源
sudo sed -i 's/archive.ubuntu.com/mirrors.aliyun.com/g' /etc/apt/sources.list

# 4. 预装 Node.js
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs

# 5. 配置 npm 镜像
npm config set registry https://registry.npmmirror.com

# 6. 预装 Playwright 依赖
sudo npx playwright install-deps chromium

# 7. 清理缓存，减小体积
sudo apt clean
sudo rm -rf /var/lib/apt/lists/*
npm cache clean --force

# 8. 导出为 tar 包
wsl --export Ubuntu-22.04 openclawcn-ubuntu.tar

# 9. 压缩（约 250-300MB）
gzip openclawcn-ubuntu.tar
```

**安装时导入（完全静默）**：

```powershell
# 解压预配置镜像（从安装包中）
Expand-Archive -Path "openclawcn-ubuntu.tar.gz" -DestinationPath $tempDir

# 静默导入，无任何窗口弹出

# 设置默认用户（避免以 root 运行）
# 在导入的 WSL 中执行
wsl -d OpenClawCN -- bash -c "echo '[user]\ndefault=openclawcn' | sudo tee /etc/wsl.conf"
```

### 附录 B：常见问题

**Q: 为什么安装时需要管理员权限？**
A: 安装过程需要启用 Windows 的 Linux 子系统 (WSL) 功能，这是 Windows 的安全要求。安装完成后，日常使用不再需要管理员权限。

**Q: 如何以管理员身份运行安装程序？**
A: 右键点击安装程序文件，在弹出的菜单中选择「以管理员身份运行」。

**Q: 为什么需要开启虚拟化？**
A: OpenClawCN 使用 Windows 的 Linux 子系统来运行高级功能，这需要虚拟化支持。

**Q: 开启虚拟化会影响电脑性能吗？**
A: 不会，虚拟化是 CPU 的内置功能，开启后对日常使用没有影响。

**Q: 我的电脑不支持虚拟化怎么办？**
A: 2015 年后的电脑几乎都支持虚拟化。如果确实不支持，可以尝试使用 OpenClawCN 的纯 Web 版本（功能会受限）。

**Q: 安装需要多长时间？**
A: 首次安装约 5-15 分钟，取决于网络速度。
