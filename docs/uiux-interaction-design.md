## 第一部分：设计总纲

### 1.1 设计原则

**核心理念：渐进式披露（Progressive Disclosure）**

用户不需要一次看到所有功能。根据使用阶段，逐步展示更高级的选项。

| 原则 | 解释 | 落地方式 |
|------|------|---------|
| **零配置可用** | 第一次打开就能用，不需要填任何参数 | 安装向导 + 智能默认值 |
| **看得懂** | 所有文字用人话说，不用技术术语 | 全中文 i18n + 类比说明 |
| **不怕搞坏** | 用户随便操作不会导致系统崩溃 | 危险操作二次确认 + 一键恢复 |
| **随时能回来** | 任何时候都能回到安全状态 | 全局"恢复默认"按钮 + 配置历史 |
| **高级功能不挡路** | 不会的功能不会困扰用户 | 折叠/隐藏高级选项 |

---

### 1.2 用户画像与场景

**用户画像 A：小白用户（60%）**
- 不懂技术，只想通过钉钉/飞书跟 AI 聊天
- 希望"装上就能用"
- 看到英文/技术名词就害怕
- 只用 3 个页面：聊天、概览、技能

**用户画像 B：技术用户（30%）**
- 会用命令行，懂 API Key、Docker 这些概念
- 想精细调参数、接多个 AI 厂商
- 会用配置编辑器和调试面板

**用户画像 C：运维/管理员（10%）**
- 负责在云服务器上部署
- 需要监控日志、管理会话、配置定时任务
- 用到所有 14 个 Tab

---

### 1.3 当前架构审计总结

**现有架构**（基于源码审查）：

```
导航结构（4 组 14+ Tab）：
├── 聊天组：chat
├── 控制面板组：overview, free-models, usage, channels, instances, sessions, cron
├── 智能体组：playground, skills, nodes
├── 设置组：config, debug, logs
└── 文档（独立）：docs
```

**现有评分**：

| 维度 | 得分 | 问题 |
|------|------|------|
| 视觉设计 | 8/10 | 整洁现代，暗色主题好看 |
| 功能完整度 | 9/10 | 覆盖全面 |
| 小白友好度 | 4/10 | 导航复杂、缺乏引导、部分英文 |
| 交互流畅度 | 7/10 | 表单交互好，但首屏设计问题大 |
| 信息架构 | 5/10 | 14个Tab对60%用户来说太多 |

**7 个核心问题**（上一轮审计已识别）：

1. 概览页首屏是 Gateway 连接表单（技术感太重）
2. 14 个导航 Tab 信息过载
3. Notes 卡片纯英文
4. 20+ 处硬编码字符串绕过 i18n
5. 配置页 "Update" 按钮语义模糊
6. 原始 JSON 模式无语法高亮
7. 无新用户引导流程

## 第二部分：全局架构重设计

### 2.1 导航结构重构

**设计策略：双层导航 — 核心Tab + 高级折叠**

将 14 个 Tab 重新分为两层：

**第一层：常驻导航（5 个 Tab）— 所有用户都能看到**

```
┌─────────────────────────────────┐
│  💬 对话    首页                   │  ← 默认选中
│  📊 概览    系统状态+快捷设置       │
│  ⚡ 技能    能力管理               │
│  📱 渠道    聊天工具连接            │
│  ⚙️ 设置    所有配置               │
└─────────────────────────────────┘
```

**第二层：高级功能（折叠区）— 点击展开才看到**

```
┌─────────────────────────────────┐
│  ▸ 高级功能                       │  ← 默认折叠
│    🎮 体验场    试用技能           │
│    🆓 免费模型  省钱管理           │
│    📈 用量统计  费用追踪           │
│    ⏰ 定时任务  自动化             │
│    👥 会话管理  对话历史           │
│    🖥️ 实例管理  多实例             │
│    🔗 节点管理  分布式             │
│    🐛 调试面板  开发调试           │
│    📜 系统日志  排查问题           │
│    📖 文档     帮助文档           │
│    💬 反馈     问题反馈           │
└─────────────────────────────────┘
```

**交互逻辑**：

```
用户首次打开
  │
  ├─ 看到 5 个核心 Tab（简洁、不怕）
  │
  ├─ 如果想找更多功能 → 点击"高级功能" → 展开看到全部
  │
  ├─ 展开状态记住（localStorage） → 下次打开保持展开
  │
  └─ "高级功能"标签显示数字角标
     └─ 有需要关注的事项（如未配置的渠道）时才显示
```

**技术实现要点**：

修改 `navigation.ts` 中的 `TAB_GROUPS`：

```
// 现有：4 组
// 改为：2 组（核心 + 高级）
// 高级组默认折叠，state.settings.navGroupsCollapsed["advanced"] = true
```

---

### 2.2 页面布局体系

**顶栏重设计**

现有顶栏从左到右：菜单 → Logo → 技术支持 → TecbinAI → Health 状态 → 主题切换

**问题**：Health 显示 "OK" 或 "Offline"（英文），TecbinAI 推广链接占位过大。

**改进方案**：

```
┌─────────────────────────────────────────────────────────┐
│ ☰ ClawbotCN              [状态: ✅ 已连接]  [🌙/☀️/💻]  │
│    全栈国内运行               ⭐技术支持                  │
└─────────────────────────────────────────────────────────┘
```

变化点：
1. "Health OK" → "✅ 已连接" / "❌ 未连接" / "⏳ 启动中"（中文）
2. TecbinAI 推广链接移到侧边栏底部（已有），顶栏不重复
3. 技术支持按钮保留，但位置调整到右侧与状态同行

---

### 2.3 全局组件规范

**卡片组件**

所有页面内容用卡片承载，统一规范：

```
┌─────────────────────────────┐
│ 📊 卡片标题                   │ ← 左侧图标+标题
│ 一句话说明这个卡片是干什么的   │ ← 副标题（中文）
├─────────────────────────────┤
│                             │
│   卡片内容                   │
│                             │
├─────────────────────────────┤
│ [操作按钮]            [链接] │ ← 底部操作区
└─────────────────────────────┘
```

**按钮层级**

| 级别 | 样式 | 用途 | 例子 |
|------|------|------|------|
| 主要 | 实心蓝色 | 页面最重要的操作 | "保存"、"连接" |
| 次要 | 描边灰色 | 辅助操作 | "取消"、"重载" |
| 危险 | 实心红色 | 不可逆操作 | "删除"、"重置所有" |
| 链接 | 纯文字蓝色 | 跳转、查看详情 | "查看文档"、"高级配置" |

**表单控件**

| 控件 | 交互说明 |
|------|---------|
| 开关（toggle） | 点击立即生效，无需额外保存按钮 |
| 下拉框（select） | 选择后出现"保存"按钮（非即时生效） |
| 输入框（input） | 失焦时校验，底部显示错误提示 |
| 密码框（password） | 右侧"眼睛"图标切换显示/隐藏 |

### 3.3 功能发现引导

**现有能力**：`capability-detect.ts` 已实现了基础发现功能，包括：
- 首次访问检测（localStorage）

### 6.3 配置变更流程

```
[用户修改配置项]
    │
    ├─ 表单模式：onChange 更新 configForm 状态
    │   └─ 实时计算 diff（与 configFormOriginal 对比）
    │
    ├─ 原始模式：onChange 更新 configRaw 文本
    │   └─ 实时校验 JSON5 语法
    │
    ▼
[底部操作栏更新]
    │
    ├─ 有变更 → "保存"和"保存并重启"按钮变为可用
    │
    ├─ 点击"重载"
    │     └─ 丢弃变更 → 重新从服务器加载配置
    │
    ├─ 点击"保存"
    │     ├─ POST 到 gateway API (config.save)
    │     ├─ 乐观并发控制（基于 hash 检查冲突）
    │     ├─ 成功 → 显示"✓ 已保存"提示
    │     └─ 失败 → 显示错误信息
    │           ├─ hash 冲突 → "配置已被其他地方修改，请重载"
    │           └─ 网络错误 → "保存失败，请重试"
    │
    └─ 点击"保存并重启"
          ├─ 先执行保存
          ├─ 保存成功后 → 发送 apply 命令
          ├─ Gateway 服务重启（1-2 秒断开）
          ├─ WebSocket 断开 → 自动重连
          └─ 重连成功 → 重新加载配置 → 显示"✓ 已应用"
```
