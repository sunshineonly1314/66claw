## 三、单次对话 Token 消耗拆解

基于 ClawdBot 代码实际分析:
- `src/agents/system-prompt.ts` (~719行，动态组装)
- `skills/wechat-desktop/SKILL.md` (~10,465 bytes)
- `skills/desktop-control/SKILL.md` (~4,779 bytes)

### 每次 API 调用的输入 Token 构成

| 组件 | Token数 | 是否可缓存 | 说明 |
|------|--------|-----------|------|
| System Prompt | ~12,000 | 可缓存 | 每次请求固定前缀 |
| WeChat Skill | ~7,500 | 可缓存 | 加载后固定 |
| Desktop Control Skill | ~3,500 | 可缓存 | 加载后固定 |
| **固定前缀小计** | **~23,000** | **75%折扣** | |
| 对话历史 (20轮) | ~15,000 | 不可缓存 | 设置 dmHistoryLimit=20 |
| 当前用户消息 | ~150 | 不可缓存 | 中文客服消息 |
| Memory 检索结果 | ~2,000 | 不可缓存 | 客户画像 |
| **变动部分小计** | **~17,150** | **全价** | |

### 每次 API 调用的输出 Token

| 场景 | 输出Token | 说明 |
|------|----------|------|
| 简单回复 | ~300 | "好的，已为您查询" |
| 标准客服回复 | ~800 | 包含产品信息、操作指引 |
| 复杂回复+工具调用 | ~1,500 | 需要操作桌面/查系统 |
| **取均值** | **~800** | |

### 单次 API 调用成本

```
固定前缀（缓存命中）: 23,000 tokens × ¥1.08/百万 = ¥0.0248
变动输入（缓存未命中）: 17,150 tokens × ¥4.32/百万 = ¥0.0741
输出:                    800 tokens × ¥21.60/百万 = ¥0.0173
────────────────────────────────────────────────────
单次 API 调用成本 ≈ ¥0.116（约 1.2 分钱）
```

### 单次客户对话成本

- 普通对话 (4轮): ¥0.116 × 4 ≈ **¥0.46**
- 含桌面操作 (7轮): ¥0.116 × 7 ≈ **¥0.81**

## 四、单工位日/月成本核算

### 场景假设: 中等业务量客服工位

| 参数 | 数值 | 说明 |
|------|------|------|
| 日接待客户数 | 80 | 中等业务量 |
| 平均对话轮次 | 4 轮 | 咨询→回复→追问→结束 |
| 含桌面操作比例 | 30% | 需要查系统的比例 |
| 工作时间 | 12h/天 | 早8-晚8 |

### 每日 Token 消耗

```
每日 API 调用次数:
  - 普通对话: 80 × 0.7 × 4轮 = 224 次
  - 含操作对话: 80 × 0.3 × 7轮 = 168 次
  - 合计: 392 次/天

每日输入 Token:
  - 缓存命中: 392 × 23,000 = 9,016,000 tokens (~900万)
  - 缓存未命中: 392 × 17,150 = 6,722,800 tokens (~672万)

每日输出 Token:
  - 392 × 800 = 313,600 tokens (~31万)
```

### 每日 Token 费用

| 项目 | Token数 | 单价(¥/百万) | 费用 |
|------|--------|-------------|------|
| 输入(缓存命中) | 9,016,000 | 1.08 | ¥9.74 |
| 输入(缓存未命中) | 6,722,800 | 4.32 | ¥29.04 |
| 输出 | 313,600 | 21.60 | ¥6.77 |
| **每日合计** | | | **¥45.55** |

### 月度 Token 费用

```
月度 Token 成本 = ¥45.55 × 30天 ≈ ¥1,367/月
```

## 九、降本优化手段

| 优化手段 | 预期降幅 | 说明 |
|----------|---------|------|
| 限制 dmHistoryLimit=10 | -20% | 减少历史上下文 |
| 精简 System Prompt | -15% | 去掉非客服功能的内容 |
| 用 Kimi K2 Thinking 替代 K2.5 | -17% | 输出价格更低 |
| 简单问题用规则引擎兜底 | -30% | FAQ 不走 LLM |
| 批量采购 API 折扣 | -10~20% | 联系 Moonshot 商务 |

极限优化后，中等业务量成本可降至 ¥800-900/月，毛利率可达 70%+。

## 十、OPC 实操路径

### Phase 1: 验证期（0-3个月）

- 目标: 签下 3-5 个付费客户，月收入 ¥10,000+
- 选一个垂直行业（推荐: 教育/医美/电商其一）
- 做 Demo 视频展示微信自动客服全流程
- 找 5-10 个目标客户免费试用，用数据说话
- 交付: 帮客户在 Windows 电脑上部署，远程运维

### Phase 2: 标准化（3-6个月）

- 目标: 月收入 ¥50,000+，客户 15-20 个
- 部署流程自动化（一键安装脚本）
- 开发管理后台（基于现有 Web UI 扩展）
- 建立话术模板库（按行业分类）
- 设计合规方案（消息审计、敏感词过滤）

### Phase 3: 规模化（6-12个月）

- 目标: 月收入 ¥200,000+
- 招 1-2 个销售/交付人员
- 建立代理商/分销体系
- 输出行业解决方案白皮书

## 十一、风险提示

1. **微信封号风险**: 桌面自动化本质是"外挂"，需控制操作频率、模拟人类节奏
2. **合规风险**: 自动回复需明确告知用户是 AI，部分行业有监管要求
3. **LLM 成本波动**: API 定价可能调整，需关注
4. **竞争**: 影刀、微伴助手等已有市场，差异化在于 AI 原生 + 自然语言编排
