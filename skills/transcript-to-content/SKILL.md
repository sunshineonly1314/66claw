# 会议记录 → 结构化内容

将原始会议记录及培训会话录音转化为结构化学习材料、文档及可操作洞察。

## 何时使用本skills

当出现以下情形时，请使用本skills：  
- 用户提供了会议记录、培训会话录音或入职笔记  
- 用户要求从口头/对话类数据中生成结构化学习材料  
- 用户请求从会议中提取关键信息、操作流程或待办事项  
- 用户需要基于会议记录创建培训文档、标准作业程序（SOP）或参考材料  
- 用户希望从培训会话中生成学习指南、检查清单或FAQ文档  

## 核心工作流  

### 第一步：理解用户需求  

识别用户所需的内容类型：  

| 输出类型 | 使用场景 |  
|----------|----------|  
| **主知识源（Master Knowledge Source）** | 全面的结构化学习模块，含元数据、术语表、SOP、细节说明与评估题 |  
| **演示文稿/幻灯片** | 用于授课或参考的可视化培训材料 |  
| **SOP文档** | 分步式流程操作文档 |  
| **速查表（Quick Reference Sheet）** | 关键要点与操作流程的一页式精简摘要 |  
| **学习指南（Study Guide）** | 为学习者组织的复习材料 |  
| **检查清单（Checklist）** | 从操作流程中提取的可执行任务列表 |  
| **FAQ文档** | 培训内容中提炼的常见问题与解答 |  
| **待办事项列表（Action Items List）** | 会议讨论中产生的任务、负责人及截止时间 |  

### 第二步：定位并分析原始资料  

**若会议记录位于项目目录中：**  
```bash
ls -lah /home/ubuntu/projects/[project-name]/
```  

**按关键词搜索相关内容：**  
```bash
grep -ri "keyword" /home/ubuntu/projects/[project-name]/*.md
```  

**阅读并识别：**  
- 主要主题与概念  
- 分步操作流程  
- 关键警示或细节说明  
- 术语与定义  
- 真实案例或场景  
- 待办事项与决策结论  
- 提出的问题与对应解答  

### 第三步：提取结构化内容  

应用**链式思维（Chain of Thought）处理流程：**  

1. **通读全部会议记录**，把握宏观背景与整体主题  
2. **分离独立主题**，归类相关信息  
3. **精准提取事实、步骤与定义**  
4. **剔除口语填充词**（如“呃”、“嗯”、“我觉得”、“可能”、“我们试试”）  
5. **转换为祈使语态、权威性语言**（使用动作动词）  
6. **对未知内容使用 `[MISSING INFO]` 标记**，切勿虚构  

**针对主知识源（Master Knowledge Source）格式：**  

请参阅 `/home/ubuntu/skills/transcript-to-content/references/master-knowledge-source-format.md` 获取完整模式与示例。  

需提取以下部分：  
- **模块元数据：** 主题与学习目标（一句话表述）  
- **关键术语：** 行业术语、缩略语、工具的定义  
- **标准作业程序（SOP）：** 以“动作 > 结果”格式编写的编号步骤  
- **关键细节说明：** 警示、后果、最佳实践、上下文说明  
- **评估数据：** 严格依据内容生成3–5道单选题  

**针对其他文档类型：**  

- **检查清单：** 提取带复选框的顺序化行动项  
- **FAQ：** 识别会议中提出的问题及提供的答案  
- **学习指南：** 按主题组织，含核心概念与示例  
- **待办事项：** 提取含负责人与截止时间的任务  

### 第四步：应用品牌标识（如适用）  

**若用户提供品牌素材：**  
- 向用户索取Logo文件、品牌色与字体偏好  
- 将Logo存入工作目录  
- 一致应用品牌色（主色用于强调、高亮、图表）  
- 使用指定字体，或选用专业网络字体（Inter、Roboto、Open Sans）  

**若未提供品牌标识：**  
- 使用简洁、专业的中性色板  
- 聚焦清晰性与可读性  
- 全篇保持样式一致性  

### 第五步：生成交付成果  

#### 演示文稿  

请参阅 `/home/ubuntu/skills/transcript-to-content/references/presentation-guidelines.md` 获取详细指南。  

**工作流：**  
1. 使用 `slide_initialize` 工具初始化演示文稿  
2. 创建大纲（默认最多12页，除非用户另行指定）  
3. 若用户提供Logo，则复制至项目目录：  
   ```bash
   cp [logo-path] [project-dir]/logo.png
   ```  
4. 使用 `slide_edit` 工具逐页编辑幻灯片  
5. 使用 `slide_present` 工具进行演示  
6. 如用户提出需求，则导出PDF：  
   ```bash
   manus-export-slides manus-slides://[version-id] pdf
   ```  

**标准演示文稿结构：**  
1. 标题页  
2. 定义/概述  
3. 分步内容（4–6个步骤）  
4. 关键成功要素  
5. 常见误区  
6. 核心要点  
7. 结束页  

**设计要求：**  
- 使用品牌色（若已提供）或专业中性色板  
- 每页幻灯片均需展示Logo（若已提供）  
- 高度不得超过720px  
- 采用简洁、基于网格的版式  
- 禁止使用浓重阴影、过度圆角或动画效果  

#### SOP文档  

创建Markdown文档，包含：  
- 清晰的层级结构（H1、H2、H3）  
- 使用祈使语态编写的编号操作流程  
- 以引用块（blockquote）呈现的警告/注意事项  
- 用于参考数据的表格  
- 在适用处添加行内引用  

**示例结构：**  
```markdown
# [Procedure Name]

## Overview
[Brief description]

## Prerequisites
- [Required items or conditions]

## Procedure
1. [Action step]
2. [Action step]
3. **CRITICAL:** [Important step with warning]

## Troubleshooting
- **Issue:** [Problem]
  **Solution:** [Resolution]
```  

#### 速查表  

创建简洁的一页式文档，包含：  
- 以定义列表格式呈现的关键术语  
- 以编号列表呈现的核心步骤  
- 以高亮框呈现的关键警示  
- 常见场景及其解决方案  

#### 学习指南  

按主题组织，包含：  
- 学习目标  
- 含解释的核心概念  
- 示例与真实场景  
- 练习题  
- 补充资源  

#### 检查清单  

提取行动项，包含：  
- 复选框格式（`- [ ]`）  
- 清晰、可执行的语言  
- 合理的逻辑顺序  
- 可选：优先级标识或时间预估  

#### FAQ文档  

结构如下：  
- 问题以加粗显示  
- 答案使用清晰、简洁的语言  
- 可选：相关问题或参考资料  

#### 主知识源（Master Knowledge Source）  

严格遵循 `references/master-knowledge-source-format.md` 中定义的模式：  
- 仅输出结构化内容（不添加引言或结语）  
- 严格使用Markdown格式  
- 将所有口语化表达转换为权威性指令  
- 对未知内容使用 `[MISSING INFO]` 标记  

## 质量标准  

**内容准确性：**  
- 所有内容必须严格基于原始资料  
- 绝不虚构步骤、数据或信息  
- 对不完整的流程，明确使用 `[MISSING INFO]` 标记  
- 术语定义须与原始资料核对一致  

**清晰性与可读性：**  
- 指令使用祈使语态（“单击”、“导航至”、“设置”）  
- 维持清晰的视觉层级  
- 通过标题与列表确保内容易于快速浏览  
- 彻底删除所有口语填充词  

**一致性：**  
- 全篇贯彻统一的格式规范  
- 术语使用保持一致  
- 类似章节结构保持统一  

**品牌标识（如适用）：**  
- 品牌色应用须保持一致  
- 所有品牌化材料均须包含Logo  
- 应用指定字体  
- 遵循品牌风格指南  

## 常见模式  

### 模式1：单一主题培训演示文稿  
用户提供单一主题的会议记录 → 提取核心内容 → 制作8–12页演示文稿  

### 模式2：多主题→学习模块  
用户提供多个会议记录 → 分别提取为独立模块 → 以结构化文档形式交付  

### 模式3：速查型SOP  
用户需要特定流程 → 提取相关步骤 → 制作简洁SOP文档  

### 模式4：培训概览摘要  
用户请求某主题摘要 → 搜索会议记录 → 提取并综合关键点 → 以Markdown格式交付  

### 模式5：入职检查清单  
用户提供入职会议记录 → 提取顺序化任务 → 制作带复选框的检查清单  

### 模式6：会议待办事项  
用户提供会议纪要 → 提取决策与任务 → 制作含负责人信息的待办事项列表  

## 故障排查  

**问题：** PDF中幻灯片显示为空  
**解决方法：** 检查内边距值；减小内边距、调整间距，确保内容适配720px高度  

**问题：** Logo未显示  
**解决方法：** 确认Logo已复制至项目目录；HTML中使用绝对路径  

**问题：** 内容看似不完整  
**解决方法：** 使用 `[MISSING INFO]` 明确标记，切勿猜测；若属关键信息，向用户请求澄清  

**问题：** 演示文稿超出高度限制  
**解决方法：** 缩小字号、减少间距、压缩内容，或拆分为更多幻灯片  

**问题：** 输出中口语填充词过多  
**解决方法：** 加强过滤；移除“我觉得”、“可能”、“呃”、“嗯”、“我们试试”等短语  

**问题：** 操作流程缺乏清晰度  
**解决方法：** 转换为祈使语态；使用动作动词；对重要步骤添加“CRITICAL”前缀
