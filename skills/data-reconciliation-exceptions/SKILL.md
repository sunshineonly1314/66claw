# 数据质量与比对校验（含异常报告与零静默失败机制）

## 目的  
基于稳定标识符（工号、驾驶证号、司机卡号、司机资格证号）对多源数据进行比对校验，生成异常报告，并实施“零静默失败”检查。

## 适用场景  
- **触发条件：**  
  - 对这两个数据源执行比对，并生成带原因说明的异常报告。  
  - 跨文件匹配姓名与工资编号，并标记所有无法关联的记录。  
  - 构建“零静默失败”校验点：若统计数量不一致，则中断流水线。  
  - 生成周度差异报告，涵盖缺失记录、重复记录及日期断层。  
  - 设计数据质量记分卡，设定阈值与红色预警项。  
- **不适用场景：**  
  - 需要无约束的模糊匹配，且无明确接受标准。  
  - 所有数据源中均不存在任何稳定标识符。  

## 输入  
- **必需：**  
  - 至少两个数据集（CSV/XLSX 格式），包含工号和/或司机证件号码。  
  - 明确指定需比对的字段（例如：姓名、有效期）。  
- **可选：**  
  - 标准化规则（大小写、空格、标点符号处理等）。  
  - 门限值设定（如最大允许缺失率等）。  
- **示例：**  
  - 工资系统导出表 + 合规登记表  
  - 来自不同系统的两份周度导出数据  

## 输出  
- 比对校验方案（匹配规则、标准化方法、连接策略）。  
- 异常报告规范（CSV 字段定义 + 原因代码）及差异校验逻辑。  
- 可选产物：`assets/exceptions-report-template.csv` + `references/matching-rules.md`。  
成功标准：每条记录均被明确归类（已匹配 / 缺失 / 重复 / 字段不一致 / 标识符无效），且均有明确原因；流水线在检测到异常时自动中止。

## 工作流程  
1. 确认数据源及主键优先级（工号 → 司机卡号 → 驾驶证号 → 司机资格证号）。  
2. 列标准化：  
   - 去除首尾空格；统一大小写；对证件号字段移除常见标点符号。  
3. 标识符校验：  
   - 标记空白值/格式无效项；识别各数据源内部的重复标识符。  
4. 关联匹配：  
   - 优先基于工号进行精确匹配；仅对剩余未匹配项尝试二级键匹配。  
5. 生成带原因的异常分类：  
   - A/B 源中缺失、标识符重复、字段值不一致、标识符无效。  
6. “零静默失败”校验点：  
   - 统计数量在容差范围内；未匹配率低于阈值；重复量突增即告警。  
7. **需暂停并询问用户的情形：**  
   - 字段尚未映射；  
   - 存在多个相互冲突的 ID，且无明确优先级；  
   - 未指定预期容差范围。  

## 输出格式  
```csv
exception_type,reason,source_a_id,source_b_id,pay_number,name,field,source_a_value,source_b_value
```  

原因代码：`MISSING_IN_A`、`MISSING_IN_B`、`MISMATCH`、`DUPLICATE_KEY`、`INVALID_KEY`。  

## 安全性与边界情况处理  
- 默认为只读模式；禁止自动修改源数据；所有异常均路由至人工复核。  
- 优先采用确定性匹配规则；除非明确要求，否则避免模糊匹配。  
- 必须始终生成异常报告；绝不静默丢弃未匹配行。  

## 示例  
- 输入：“工资表 vs 合规登记表；按工号匹配；标记姓名不一致项。”  
  输出：关联方案 + 不一致原因说明 + 异常报告结构定义。  

- 输入：“部分行工号为空。”  
  输出：启用二级键匹配 + 对真正无法匹配的行标注“标识符无效”异常。
