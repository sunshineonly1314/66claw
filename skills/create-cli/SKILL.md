# 创建 CLI

设计 CLI 表层接口（语法 + 行为），以人为本，兼顾脚本友好性。

## 首先执行

- 阅读 `agent-scripts/skills/create-cli/references/cli-guidelines.md` 并将其作为默认评估标准。
- 上游/完整指南：https://clig.dev/（提出修改建议：https://github.com/cli-guidelines/cli-guidelines）
- 仅提出最少必要澄清问题，以锁定接口定义。

## 快速澄清

提问后，若用户不确定，则基于最佳猜测采用默认值继续：

- 命令名称 + 一句话说明用途。
- 主要用户：人类、脚本，还是两者兼有。
- 输入来源：参数 vs stdin；文件 vs URL；密钥（绝不可通过标志传入）。
- 输出契约：人类可读文本、`--json`、`--plain`、退出码。
- 交互性：是否允许提示？是否需要 `--no-input`？破坏性操作是否需要确认？
- 配置模型：标志/环境变量/配置文件；优先级；XDG 规范 vs 仓库本地配置。
- 平台/运行时约束：macOS/Linux/Windows；单二进制 vs 运行时依赖。

## 交付成果（需输出内容）

设计 CLI 时，产出一份紧凑规范，供用户直接实现：

- 命令树 + USAGE 概要。
- 参数/标志表格（类型、默认值、必选/可选、示例）。
- 子命令语义（各子命令功能；是否幂等；状态变更）。
- 输出规则：stdout vs stderr；TTY 检测；`--json` / `--plain`；`--quiet` / `--verbose`。
- 错误 + 退出码映射（主要失败模式）。
- 安全规则：`--dry-run`、确认机制、`--force`、`--no-input`。
- 配置/环境变量规则 + 优先级（标志 > 环境变量 > 项目配置 > 用户配置 > 系统配置）。
- Shell 补全方案（如相关）：安装/可发现性；生成命令或打包脚本。
- 5–10 个典型调用示例（常见流程；含管道/stdin 示例）。

## 默认约定（除非用户另有说明）

- `-h/--help` 始终显示帮助并忽略其他参数。
- `--version` 将版本号输出至 stdout。
- 主要数据输出至 stdout；诊断/错误信息输出至 stderr。
- 添加 `--json` 以支持机器输出；考虑添加 `--plain` 以提供稳定、面向行的文本。
- 仅当 stdin 是 TTY 时才提示；`--no-input` 禁用提示。
- 破坏性操作：交互式下需确认；非交互式下需 `--force` 或显式指定 `--confirm=...`。
- 尊重 `NO_COLOR`、`TERM=dumb`；提供 `--no-color`。
- 处理 Ctrl-C：快速退出；限定清理范围；尽可能采用“仅崩溃”（crash-only）设计。
