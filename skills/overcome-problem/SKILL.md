# 克服任何问题

将障碍转化为可解决的步骤。结构化思维优于蛮力尝试。

## 功能说明

- **问题分解** — 将复杂挑战拆解为独立、可管理的子问题
- **行动计划** — 生成具备清晰依赖关系的分步执行路径
- **障碍识别** — 在阻碍进展前预先识别潜在阻塞点
- **进度追踪** — 实时监控执行进展，并在过程中动态调整方向

## 使用方法

### 定义问题
清晰陈述所面临的挑战。什么在阻碍你？成功的标准是什么？

### 拆解问题
从八个维度进行分解：功能、技术、时间、资源、风险、利益相关方、先例、创意。

### 制定行动计划
按依赖关系排序任务；识别可并行开展的工作；标注关键路径项。

### 追踪进度
执行过程中实时更新状态；记录遇到的阻碍；若前提假设被打破，则触发重新分析。

### 复盘障碍
陷入停滞时，重新审视原始指令：发生了哪些变化？遗漏了哪些要点？更新后重试。

## 问题解决框架

**定义** — 明确问题陈述；阐明约束条件与成功标准。

**分析** — 运用多重视角（技术、财务、时间、创意等）展开分析。

**生成方案** — 头脑风暴至少 3 种可行路径；暂不筛选。

**选择方案** — 选取杠杆效应最高的路径，并说明理由。

**执行** — 推行行动计划；实时跟踪各项假设。

**复盘** — 评估结果：哪些有效？指令需如何更新？

## 实用提示

- 从约束入手。问题本质是瓶颈谜题，优先解除最紧要的约束。
- 思考基本单元。最小的构成模块是什么？由此向上构建。
- 注重乘法效应，而非简单叠加。每个系统都应放大其下所有层级的效能。
- 优先并行，而非串行。寻找彼此独立的工作流，同步推进。
- 所有数据均保留在本地机器上。无云端依赖，完全掌控隐私。
