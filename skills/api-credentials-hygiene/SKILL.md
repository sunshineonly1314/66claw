# API 凭据规范：环境变量、轮换、最小权限、可审计性

## 目的
审计并加固 API 凭据处理（环境变量、隔离、轮换计划、最小权限、可审计性）。

## 何时使用
- 触发场景：
  - 加固当前集成的凭据配置，将密钥迁移至环境变量。
  - 为这些 API 设计密钥轮换计划，确保轮换过程停机时间最短。
  - 审计该服务是否遵循最小权限原则，并记录每个密钥的具体权限范围。
  - 为此项目创建环境变量映射表及安全的 `.env` 模板。
  - 实现开发与生产环境的凭据隔离，并配备清晰的审计追踪机制。
- **不适用场景**：
  - 试图未经授权获取密钥或绕过安全控制。
  - 需要法律/合规部门审批（本 skill 仅输出技术文档，不提供法律意见）。

## 输入
- 必需项：
  - 集成/API 列表，及其当前凭据的存储位置与使用位置。
  - 部署上下文（本地开发、服务器、容器、n8n 等）。
- 可选项：
  - 当前配置文件/脱敏代码片段（如 `.env`、compose 文件、systemd 配置、n8n 凭据列表等）。
  - 组织规范（如轮换周期、首选密钥管理器）。
- 示例：
  - “密钥硬编码在 Node.js 脚本和 n8n 的 HTTP 请求节点中。”
  - “我们拥有独立的开发与生产 n8n 实例，需实现凭据隔离。”

## 输出
- 凭据映射表（服务 → 环境变量 → 权限范围/作用域 → 所有者 → 轮换周期）。
- 轮换操作手册（含具体步骤及回滚方案）。
- 最小权限检查清单与审计日志规划。
- 可选：`.env` 模板（仅含占位符）。
成功标准 = 无密钥被提交至代码库或嵌入代码中，权限已最小化，轮换步骤已文档化，且可审计性已明确定义。

## 工作流
1. 凭据清点：
   - 明确其存储位置、使用位置及责任人。
2. 定义隔离策略：
   - 开发环境 vs 生产环境；人工账户 vs 服务账户；按集成边界划分。
3. 将密钥迁移至环境变量 / 密钥管理器引用：
   - 创建环境变量映射表，并更新配置方案（禁止在代码/工作流中直接嵌入原始密钥）。
4. 最小权限：
   - 针对每个 API，逐条列举必需操作，并据此缩减权限范围/角色。
5. 轮换计划：
   - 若支持，采用双密钥重叠机制；制定最小停机时间的轮换步骤及回滚方案。
6. 可审计性：
   - 明确需记录的事件类型（如认证失败、令牌刷新、密钥使用行为——若平台支持）。
7. **暂停并询问用户**，当出现以下任一情况时：
   - 必需操作尚不明确；
   - 密钥注入方式不清晰；
   - 轮换周期或责任人未指定。

## 输出格式
凭据映射表模板：

```text
CREDENTIAL MAP
- Integration: <name>
  - Env vars:
    - <VAR_NAME>: <purpose> (secret/non-secret)
  - Permissions/scopes: <list>
  - Used by: <service/workflow>
  - Storage: <secret manager/env var>
  - Rotation: <cadence> | <owner> | <procedure>
  - Audit: <what is logged and where>
```

若提供模板，则仅输出 `assets/dotenv-template.example`（仅含占位符）。

## 安全性与边界情况
- 绝不输出真实密钥、令牌或私钥，一律使用占位符。
- 默认为只读模式；除非明确要求修改文件，否则仅以计划形式提出变更建议。
- 避免授予过度宽泛的权限范围/角色，除非存在经书面记录的合理需求。

## 示例
- 输入：“n8n 的 HTTP 节点中包含 API 密钥。”  
  输出：环境变量映射表 + 迁移至 n8n 凭据管理/环境变量的实施计划 + 轮换操作手册。

- 输入：“需要实现开发与生产环境的隔离。”  
  输出：两套环境变量映射表 + 命名规范 + 访问边界检查清单。
