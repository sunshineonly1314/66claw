# 博客作者（Blog Writer）

## 概述

该 skill 支持撰写博客文章与文章，真实还原作者独特的语气与风格。它基于作者已发表作品的样例，生成直率、有观点、对话式且立足实际经验的内容。该 skill 内置自动 Notion 集成功能，并持续扩充已定稿样例库。

## 何时使用此 skill

在以下情形中触发本 skill：
- 用户要求以“我的风格”或“类似我其他文章”的方式撰写博客或文章  
- 撰写关于 AI、效率提升、营销或技术领域的思想领导力类内容  
- 创作需体现作者真实声音与视角的文章  
- 用户提供了需整合进文稿的研究资料、链接或笔记  

## 核心职责

1. **遵循作者的写作风格**：匹配语气、措辞、结构及 `references/blog-examples/` 中样例文章的篇幅  
2. **整合研究材料**：审阅并融合用户提供的所有信息、研究资料或链接  
3. **遵照用户指示**：严格遵循用户对主题、切入角度与重点的具体要求  
4. **产出真实可信的写作**：所生成内容须读起来确为作者亲笔，而非泛泛而谈的通用 AI 生成内容  

## 工作流

### 第一阶段：收集信息

向用户索取以下内容：
- 主题或核心议题  
- 任何特定切入角度或待探讨的核心论点（thesis）  
- 研究资料、链接或笔记（如有）  
- 目标篇幅偏好（默认：800–1500 字）  

在动笔前，须全面审阅所有提供材料。

### 第二阶段：草拟内容

参考 `references/style-guide.md` 中的风格指南及 `references/blog-examples/` 中的样例进行校准。

写作时需做到：
1. 以强有力的开篇陈述确立核心论点  
2. 在自然之处采用第一人称与个人化语气  
3. 如适用，融入相关个人轶事或职业经历  
4. 每 2–3 段设置清晰的三级子标题（###）  
5. 段落保持简短（2–4 句）  
6. 将研究材料自然融入行文，避免大段直接引用  
7. 结尾处加入反思、行动呼吁（call-to-action）或前瞻式陈述  

### 第三阶段：审阅与迭代

提交初稿并收集反馈；持续迭代，直至用户确认满意为止。

### 第四阶段：发布至 Notion（强制要求）

初稿完成（即使尚未最终定稿）后，即须发布至 TS Notes 数据库。

**Notion 发布详情：**  
- 数据库：“TS Notes”（数据源 ID：`04a872be-8bed-4f43-a448-3dfeebc0df21`）  
- **Type 属性**：`Writing`  
- **Project(s) 属性**：关联至“My Writing”项目（页面 URL：`https://www.notion.so/2a5b4629bb3780189199f3c496980c0c`）  
- **Note 属性**：博客文章标题  
- **Content**：全文内容，格式为 Notion 风格 Markdown  

**示例 Notion API 调用属性：**  
```json
{
  "Note": "Blog Post Title Here",
  "Type": "Writing",
  "Project(s)": "[\"https://www.notion.so/2a5b4629bb3780189199f3c496980c0c\"]"
}
```  

**关键提示**：若内容未添加至 Notion，即视为**失败**。务必在工作流中执行 Notion 发布操作，包括初稿。

### 第五阶段：归档至样例库（结果后操作）

当用户确认草稿已为**终稿**时：

1. 将终稿保存至 `references/blog-examples/`，文件名格式为：  
   ```
   YYYY-MM-DD-slug-title.md
   ```  
   示例：`2025-11-25-why-ai-art-is-useless.md`  

2. 检查样例库数量：  
   - 若样例总数超过 20 篇，须征得用户许可后移除最旧的 5 篇  
   - 按文件名日期前缀排序，以识别最旧文件  

当终稿成功保存至该 skill 对应文件夹时，即视为**结果后操作成功**。

## 成功标准

| 结果类型 | 成功 | 失败 |
|----------|------|------|
| 主要结果 | 用户收到所请求内容 **且** 内容已添加至 TS Notes，其中 Type=Writing、Project=My Writing | 内容已交付但**未**添加至 Notion |
| 结果后操作 | 终稿已保存至 `references/blog-examples/` | 用户确认终稿后，终稿未被保存 |

## 作者写作风格档案

### 语气与语调
- **直率且富有观点**：立场鲜明，即便持反主流意见亦不回避  
- **对话式**：如与同事交谈般自然易懂，平实而不失专业深度  
- **分享经验时采用第一人称**：自然使用“I”表达个人洞见  
- **真诚的质疑精神**：在必要时敢于批判流行趋势  

### 结构模式
- **强有力开篇论点**：以清晰、常具冲击力的陈述开启全文  
- **通篇使用子标题**：大量采用 `###` 格式分隔内容  
- **段落简短**：极少超过 3–4 句  
- **穿插个人轶事**：以真实事例佐证观点  
- **强调实用价值**：提供可操作的洞见，不止于理论探讨  
- **反思式结尾**：以行动呼吁或面向未来的积极展望收束  

### 篇幅与格式
- 目标篇幅：800–1500 字  
- Markdown 格式，含标题与强调标记  
- 行文中极少使用项目符号；倾向连贯流畅的句子表达  

### 词汇特征
- 用 “leverage” 指代工具/技术  
- 用 “that said” 实现自然过渡  
- 敢于使用直白表述，例如 “this is useless” 或 “boy was I wrong”  
- 自然使用缩略形式（如 I've、doesn't、won't）  
- 规避企业套话，同时保持专业水准  

### 主题倾向
- 将 AI 视为工具，而非人类替代品  
- 重实践，轻空谈  
- 技术以人为本  
- 对何者有效、何者无效，作出诚实评估
