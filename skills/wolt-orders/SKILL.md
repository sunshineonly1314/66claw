# Wolt 订单 🍔

**显示名称：** Wolt 订单 🍔  
**Slug：** wolt-orders  

该 skill 为 Wolt.com 提供功能完备的助手能力：支持带丰富筛选条件的智能餐厅发现、菜单浏览、单人/多人下单、过往订单复购、实时订单追踪、自动延迟检测 + 客服联络，以及向 Slack 或其他已连接渠道主动推送通知。

## 前提条件
- 必须启用浏览器工具（推荐启用持久会话支持以实现登录）。
- 用户首次使用时需提供 Wolt 凭据（邮箱/手机号 + 密码，或 OTP 流程）。通过浏览器 cookies/配置文件安全存储会话。
- 必须已设置或在每次下单时提供配送地址。
- 对于多人订单及通知功能，应通过 channel_send 连接 Slack 或其他渠道。
- 在添加高价商品、完成结算或提交任何订单前，必须获得用户明确确认。

## 餐厅发现支持的筛选条件

| 筛选项 | 描述 | 示例用户输入 | 浏览器中如何应用 |
|--------|------|----------------|------------------|
| 菜系/类型 | 特定食物种类或类别 | “意大利菜”、“寿司”、“汉堡”、“纯素食”、“中东菜” | 在 Wolt 首页或搜索页选择菜系筛选器 |
| 价格区间 | €（便宜）至 €€€€（昂贵） | “便宜”、“€€”、“低于 100 以色列谢克尔” | 使用价格等级筛选按钮 |
| 最大距离/预计送达时间 | 按公里或分钟限制 | “3 公里以内”、“30 分钟内送达” | 按送达时间排序，或使用可用的距离筛选器 |
| 最低评分 | 星级评分阈值 | “4.5 分及以上”、“仅限高评分餐厅” | 使用评分筛选器或按最高评分排序 |
| 促销/折扣 | 特别优惠、免运费等 | “含促销”、“免运费” | 启用“优惠”或“促销”筛选器 |
| 饮食/其他需求 | 纯素食、无麸质、清真等 | “纯素食选项”、“犹太洁食” | 搜索关键词或使用商家标签 |
| 排序方式 | 最佳匹配、评分、距离、送达时间、人气 | “最近优先”、“最快送达” | 使用排序下拉菜单 |

## 餐厅发现与推荐
1. 收集用户偏好（菜系、价格、距离、评分、促销、饮食需求、关键词）。
2. 使用浏览器工具：
   - 导航至 https://wolt.com（自动识别地区，例如以色列为 https://wolt.com/il）。
   - 设置或确认配送地址。
   - 应用所有相关筛选器与排序方式。
   - 若提供了关键词，则执行搜索。
3. 抓取前 8–12 家匹配餐厅，包含：名称、菜系、评分（星级 + 评价数）、价格等级、预计送达时间/运费、距离、当前促销、简短描述。
4. 以格式化表格/列表形式呈现结果，并附关键信息。
5. 提供选项：查看更多结果、细化筛选条件、查看某家餐厅完整菜单、或查看图片/描述。
6. 若用户要求推荐，优先选择高评分 + 速度快 + 符合筛选条件的餐厅。

## 菜单浏览与购物车构建
1. 导航至所选餐厅页面。
2. 按类别（前菜、主菜、饮品等）抓取菜单。
3. 以结构化方式呈现菜单，含菜品名称、描述、价格、热门标签。
4. 向用户询问所选菜品、数量及定制要求（例如“不要洋葱”、“额外奶酪”）。
5. 在对话中维护购物车状态。
6. 定期抓取购物车摘要，获取当前总额、费用、最低起送额、预计送达时间。
7. 每次添加后均展示更新后的购物车摘要。

## 提交单人订单
1. 确认配送地址、付款方式（如有保存则优先使用）。
2. 使用浏览器以精确选项将商品加入购物车。
3. 进入结算流程，填写所有必填字段。
4. 展示最终订单摘要（商品、总额、费用、预计送达时间 ETA）。
5. 要求用户明确确认（“是/确认/下单”）。
6. 提交订单。
7. 获取订单 ID、追踪链接、预计送达时间。
8. 向用户发送确认信息 + 追踪链接，并推送到指定渠道。

## 提交多人订单
1. 确认餐厅、配送地址及小组详情（截止时间、预期参与人数）。
2. 使用浏览器在 Wolt 上启动 **Group Order**（多人订单，Wolt 原生功能）。
3. 通过 channel_send（例如 Slack 主题）获取并分享多人订单链接。
4. 指导参与者通过链接加入并添加各自商品。
5. 定期监控购物车（抓取总额、参与者贡献情况（如可见））。
6. 当发起人表示“准备下单”时，完成结算并提交订单（需由发起人支付）。
7. 向小组共享最终订单确认信息、追踪链接及明细（如可用）。

## 复购过往订单
1. 导航至 Wolt 账户 → 订单/历史记录。
2. 抓取近期订单（日期、餐厅、总额、商品摘要）。
3. 展示最近 5–10 笔订单列表。
4. 用户选定后，若 Wolt 提供“Reorder”（复购）按钮则直接使用，否则手动重建购物车。
5. 按单人订单流程继续，需用户确认。

## 订单追踪
1. 接收订单 ID，或使用最新一笔订单。
2. 导航至订单追踪页面。
3. 抓取当前状态、ETA、骑手信息（如已出发）、地图描述。
4. 提供富文本更新（状态、剩余时间、备注等）。
5. 支持在持续对话中进行实时轮询（“watch mode”）。

## 处理延迟与联系客服
1. 追踪过程中，将当前时间与原始 ETA 进行比对。
2. 若延迟超过 15–30 分钟（可配置），向用户发出警报并提供联系客服选项。
3. 用户批准后，导航至订单 → 帮助/客服/聊天。
4. 使用模板消息发起聊天：“订单 #[ID] 已延迟。原预计送达时间为 [TIME]，当前状态为 [STATUS]。请协助处理。”
5. 实时转发客服回复。
6. 将延迟警报及客服更新推送至指定渠道。

## 发送通知
对所有重要事件均使用 channel_send：
- 餐厅推荐
- 购物车更新（按需）
- 订单确认 + 追踪链接
- 状态变更
- 延迟警报
- 客服互动摘要

消息格式应丰富（含 emoji、加粗、链接、订单 ID）。

## 安全与错误处理
- 未经用户明确“是/确认/下单”确认，绝不提交订单。
- 浏览器出错时，最多重试 3 次，或回退至人工指引。
- 尊重隐私：不得记录完整付款信息。
- 若登录过期，提示用户重新认证。
