# 事件与 PCN 处理包（英国适用）

## 目的
将事件/PCN 输入转化为结构化证据包：精炼的管理者简报、时间线、申诉函封面草稿、纠正措施，以及后续监控。

## 使用时机
- “使用 CCTV 录像和时间线笔记构建一份 PCN 申诉包。”
- “将这些事件记录汇总为一份精炼的管理者简报。”
- “为此事件制定纠正措施及后续监控方案。”

**切勿在以下情形中使用……**
- 请求内容为通用驾驶建议或行政事务（如催收发票、日程安排、IT 支持）。
- 未明确要求交付具体成果物，且提供信息过于模糊。

## 输入
- **必需项：**
  - 事件/PCN 基本信息：日期/时间、地点、车牌号、驾驶员、指控/违规事项
  - 证据清单（CCTV 录像、照片、车载远程信息处理数据、交货单、往来信函、门户截图等）
  - 任何截止期限（如申诉窗口期）
- **可选项：**
  - 现有时间线笔记、证人陈述、客户沟通记录
  - 用于制定纠正措施的内部政策/SOP 条款（请直接粘贴文本）
- **示例：**
  - “PCN：驶入公交专用道；附 CCTV 链接及说明；交货时间证明；需生成申诉包。”

## 输出
- `incident-manager-brief.md`
- `timeline.md`
- `appeal-pack-cover.md`（Word 可用格式）
- `corrective-actions.md`
- `follow-up-monitoring.md`（Excel 可用格式）
- 成功标准：
  - 时间顺序清晰，且所有证据均标注对应编号
  - 申诉包内容客观、准确，与所列证据保持一致
  - 纠正措施明确指定负责人及复审日期

## 工作流
1. 明确当前任务属于 **PCN 申诉**、**内部事件调查**，抑或二者兼有。
   - 若不明确 → **立即暂停并询问用户**。
2. 使用 `assets/incident-manager-brief-template.md` 编制管理者简报。
3. 使用 `assets/timeline-template.md` 构建时间线。
   - 若关键日期/时间缺失 → **立即暂停并要求用户提供**。
4. 执行证据采集标准：
   - 应用 `references/evidence-capture-standard.md`（编号标注、存储路径记录、完整性说明）。
5. 使用 `assets/appeal-pack-cover-template.docx-ready.md` 起草申诉函封面。
   - 内容须基于事实；引用证据编号；避免主观推测或无依据主张。
6. 基于 `assets/follow-up-monitoring-template.md` 提出纠正措施及监控方案。
7. 若被要求修改已有资料包 → **务必先征得用户确认**。

## 输出格式
```text
# timeline.md
| Date/time | Event | Source/evidence ref | Notes |
|----------|-------|----------------------|------|
```

## 安全性与边界情况
- 严禁捏造证据或结果。
- 若证据薄弱或相互矛盾，应标注为“未经证实”，并明确列出证据缺口。

## 示例
- 输入：“含 CCTV 录像及说明的 PCN 申诉”
  - 输出：管理者简报 + 时间线 + 申诉函封面 + 纠正措施 + 监控追踪表
