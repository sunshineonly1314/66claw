# Core PA Admin and Exec Support（核心个人助理行政与高管支持）

## PURPOSE（目的）  
将粘贴的消息、日历空闲时段、任务列表及会议记录，转化为清晰的计划、已排序的任务、适合专业场景的沟通草稿，以及会议准备/会后跟进内容——全程不执行任何最终操作（即不自动发送、不自动预约）。

## WHEN TO USE（适用场景）  
- 你需要从收到的消息和待办事项中生成每日计划与优先级任务  
- 你需要语气友好但保持专业的邮件/即时消息（DM）草稿  
- 你需要会议议程/简报，或需从会议记录中提取行动项  
- 你需要符合工作时间与约束条件的日程建议  
- 你需要一次“PA 全流程运行”，涵盖请求筛选、计划制定、草稿撰写与会后跟进  

### DO NOT USE WHEN…（不适用场景）  
- 你必须自动发送邮件或自动预约会议（本技能仅提供提案与草稿）  
- 你无法访问所需内容（无消息/日历/任务/会议记录可用）  
- 请求涉及法律、医疗或财务建议，超出基础行政协调范畴  

## INPUTS（输入）  
### REQUIRED（必需项，至少提供其一）  
- 粘贴的消息/邮件/即时消息（DM），或  
- 任务/待办清单，或  
- 日历空闲时段（空闲/忙碌时间段），或  
- 会议记录（原始笔记或转录节选）  

### OPTIONAL（可选项）  
- 相关方列表 + 偏好设置（语气、称谓、签名、响应 SLA）  
- 当日/当周的优先目标  
- 已知截止日期、差旅日、“硬性”承诺事项  

### EXAMPLES（示例）  
- 消息：“我们下周能就 Q1 规划开会吗？” + “请于周五前审阅这份文档。”  
- 日历：“周一 10:00–12:00 忙碌；周一 13:00–17:00 空闲；周二 08:00–11:00 空闲；周二 14:00–16:00 忙碌……”  
- 任务：“完成预算初稿（周三截止）、跟进供应商发票、准备 1:1 会议议程”  
- 记录：“决策：v2 版本于 2 月 3 日发布。行动项：Alex 负责更新路线图……”  

## OUTPUTS（输出）  
- 一个 Markdown 包，包含以下内容：  
  - 筛选摘要（哪些事项紧急、哪些被阻塞、哪些需决策）  
  - 日计划和/或周计划（在约束条件下建议的时间分块）  
  - 已排序任务列表（含负责人、截止日期、依赖关系）  
  - 沟通草稿（邮件/DM），含主题行；如有助益，提供 1–2 种版本  
  - 会议议程、简报及行动项  
- 一个符合 `references/pa-output-json-schema.md` 中定义 schema 的 JSON 数据块  
- 成功标准：  
  - 所有日程安排均须遵守：仅限工作日（周一至周五）、工作时间 08:00–17:00、会议最晚于 16:30 结束、周末（周六/周日）不安排会议  
  - 不执行任何发送或预约操作，仅输出草稿与提案  
  - 缺失关键信息时，必须触发 STOP-and-ASK（暂停并询问用户）  

## WORKFLOW（工作流）  
1. **输入摄取与标准化**  
   - 识别已提供的输入类型：消息、日历、任务、会议记录。  
   - 提取实体：人员、组织、日期、截止日期、会议请求、交付物。  
   - 若用户提供今日日期，则将相对日期（如“明天”）转换为明确日期；否则标记为缺失。  

2. **筛选与优先级排序**  
   - 将事项分类为：  
     - 紧急/有时效性  
     - 重要（战略性/高影响力）  
     - 常规/行政类  
     - 待处理/被阻塞（需额外信息或他人介入）  
   - 使用以下维度分配优先级（P0/P1/P2）：  
     - 截止日期临近程度  
     - 相关方职级/影响范围  
     - 完成耗时与价值比  
     - 依赖关系与阻塞点  

3. **计划生成**  
   - 构建建议计划：  
     - 若提供了日历空闲时段：仅在空闲窗口内安排时间块。  
     - 若未提供：基于默认工作日（08:00–17:00）提出计划。  
   - 遵守日程约束：  
     - 会议仅限周一至周五  
     - 工作时间为 08:00–17:00  
     - 会议最晚于 16:30 结束（不得安排结束时间晚于 16:30 的会议）  
     - 周末（周六/周日）不安排会议  
   - 仅在用户明确提供缓冲时间，或逻辑上必须时才加入缓冲；否则不得自行虚构。  

4. **沟通草稿撰写（友好但专业）**  
   - 对每条需回复的消息：  
     - 撰写 1 个主版本草稿  
     - 若消息冗长或复杂，可另附一个更简短的可选版本  
   - 每份草稿均须包含：  
     - 明确的诉求/下一步动作  
     - 如涉及日程安排，须以“可选时间”形式列出建议时段，而非最终确认  
     - 礼貌结尾及签名占位符  

5. **会议支持**  
   - 若存在会议请求：生成  
     - 议程（目的、议题、各议题时间分配、期望成果）  
     - 简报（背景、参会人、需做出的决策、预读材料、风险点）  
   - 若存在会议记录：从中提取  
     - 已做决策  
     - 行动项（含负责人与截止日期，若原文中有）  
     - 待解问题与后续跟进事项  

6. **整合输出**  
   - 按如下顺序生成 Markdown 各章节：  
     1) 筛选摘要  
     2) 已排序任务  
     3) 建议日程/计划  
     4) 沟通草稿  
     5) 会议议程/简报  
     6) 行动项与后续跟进  
   - 输出符合 schema 的 JSON 数据块。  

### STOP AND ASK THE USER（必须暂停并询问用户）IF…  
- 未提供任何可操作输入（无消息/任务/日历/会议记录）  
- 任一日程请求缺少以下至少一项：  
  - 日期范围或目标周  
  - 参与者/时区信息  
  - 会议时长或目的  
- 某条消息草稿需依赖你所不具备的事实（如价格、政策、决策、附件内容）  
- 缺少日历空闲时段，但用户指定了具体会议时间  
- 存在冲突性约束（例如：唯一可行时段均会导致会议结束时间晚于 16:30）
