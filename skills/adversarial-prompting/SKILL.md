# 对抗式提示（Adversarial Prompting）

本 skill 运用结构化的对抗式方法解决问题：生成多个解决方案，逐一严格批判其弱点，开发针对性修复措施，验证修复效果，并最终整合为排序后的推荐方案。该方法强制在选定方案前，深入分析故障模式、边界情况及意外后果。

## 何时使用本 skill

请在以下情形中使用本 skill：
- 面临需深度分析的复杂技术问题（如架构决策、调试、性能优化）  
- 解决具有多种可行路径的战略或商业问题  
- 需在实施前识别拟议方案中的薄弱环节  
- 需经验证的修复措施，以根治问题而非仅缓解表象  
- 处理高风险决策，必须预先理解潜在失败模式  
- 需要全程可见、推理详尽的综合分析  

请勿在以下情形中使用本 skill：
- 简单直接、答案显而易见的问题  
- 时间敏感、需立即行动而无法分析的决策  
- 探索与迭代本身比前期分析更有价值的问题  

## 如何使用本 skill

### 主要工作流

被调用时，对用户提出的问题执行以下七阶段流程：

#### 第一阶段：方案生成  
生成 3–7 种互不相同的解决方案。对每种方案：
- 阐明该方案背后的推理逻辑  
- 描述其核心策略  
- 概述关键步骤或组成要素  

#### 第二阶段：对抗式批判  
对每种方案，严格识别关键弱点。思考过程需涵盖：
- 边界情况与故障模式  
- 安全漏洞或风险  
- 性能瓶颈  
- 可扩展性限制  
- 可能导致方案失效的隐含假设  
- 资源约束（时间、资金、人力）  
- 意外后果  
- 灾难性故障场景  

请富有创意且全面地识别可能出错之处。

#### 第三阶段：修复方案开发  
针对每个已识别的弱点：
- 提出具体的修复或缓解策略  
- 解释该修复为何能根治问题根源  
- 描述修复措施如何与原始方案融合  

#### 第四阶段：验证核查  
逐一审查每项修复，确认其确实解决了对应弱点：
- 确认修复直指根本原因  
- 检查修复是否引入新问题  
- 标注任何剩余疑虑或权衡取舍  

#### 第五阶段：整合汇总  
将所有方案及经验证的修复整合为综合性方案：
- 融合不同方案中互补的要素  
- 消除冗余内容  
- 展示如何组合方案以形成更强有力的方法  
- 呈现最终一套可行选项  

#### 第六阶段：选项概览  
按以下维度对所有可行选项排序呈现：
- **可行性**：能否利用现有资源实际落地？  
- **影响力**：该方案在多大程度上解决了问题？  
- **风险等级**：仍可能出现哪些问题？  
- **资源需求**：所需时间、金钱与人力成本  

对每个选项，提供一段摘要，重点说明关键权衡。

#### 第七阶段：最终推荐  
明确指出首选推荐方案（单一选项或组合方案）：
- 清晰阐明为何此为最佳路径  
- 列出具体的后续实施步骤  
- 明确需追踪的关键成功指标  
- 指出需监控的早期预警信号  

### 输出格式

将完整分析分为三部分呈现：

1. **详细推演过程**：展示全部阶段（1–5）及完整推理过程  
2. **选项概览**：按优先级排序的可行方案列表（第六阶段）  
3. **最终推荐**：首选方案及实施指导（第七阶段）  

分析呈现完毕后，自动使用 `scripts/export_analysis.py` 将完整输出导出为 Markdown 文件。

## 实施注意事项

- 全程展示推理过程，确保透明  
- 对抗式批判务必彻底——揭示那些令人不安的真相  
- 修复措施须经严格验证，避免制造新问题  
- 整合汇总的目标是构建更优方案，而非简单罗列选项  
- 最终推荐必须具备可操作性，并附带清晰的下一步指引  
- 将结果导出为 Markdown，便于日后查阅与分享
